# 审批如何工作

请求会说明将发生什么、谁能决定，以及每个选择允许什么。回答之前先阅读这些后果。这里涉及两种权限：环境内部工作的权限，和改变环境边界的权限。

## 环境内部的工作

智能体程序请求运行命令或修改文件时，由有权管理该会话的人决定。会话的审批模式适用于环境现有边界之内的工作。共有四种模式：

- **询问**会在智能体程序尚未信任的动作之前请求。
- **按需询问**在程序需要时，或其文件访问规则阻止某个动作时请求。
- **自动审查**使用智能体程序自己的审核器。允许的动作会运行，被拒绝的不会。审核会在会话里显示它所用的模型和结果。自动审查从不是默认值。
- **跳过提示**让智能体在它的环境里不经询问做任何事，选择它的人要对此负责。它需要另一道把智能体限制住的边界，以及不以 root 权限运行的程序。问题和提出的计划仍需要你回应。

新会话使用所在位置的审批模式，前提是所选程序提供它。否则它从程序的默认值开始，例如 DeepSeek Harness 的**询问**。位置允许的模式和环境的边界仍然适用。

所选构建必须在此机器上通过自动审批检查才能提供**自动**模式。尚未通过或检查失败时，
审批模式选择器会说明原因。如果该构建有可运行的检查，系统管理员可以在这里选择**检查**。

Claude Code 使用其原生自动审批模式。检查会验证分类器能放行获准的动作、阻止被拒绝的动作，
并在审阅器不可用时阻止执行。检查通过后，提供方访问权限和所在位置的审批策略仍然生效。

在转发会话中，Codex 使用线程的模型进行审阅。原生登录使用其声明的首选审阅器。
线程显示所选模型，Codex 明确给出的模型名称会标为已报告。审阅可能消耗提供方额度。
单独报告的审阅用量归该线程；否则总用量以代理程序的报告为准。本来不需要审批的动作不会额外触发审阅。你对提供方的访问权限必须允许使用审阅器的模型。

例如，处于**按需询问**的会话可以运行它的常规测试，然后请求写入一个受保护的文件。**允许一次**回答这个请求。而像“我该用哪个分支？”这样的问题，在每种模式下都仍然需要你回答。

## 改变边界

对 KVM、端口或访问的请求，需要对它将打开的东西拥有权限。管理会话并不让你能在别人的主机上授予 KVM、打开端口，或交出另一个人的提供方。卡片会显示你现在能否决定。**跳过提示**、**自动审查**、会话的规则和**停止**都不能决定这些请求。

能力的策略可以允许、询问或拒绝。在允许之下，结果会记录批准它的策略。对于端口，**允许一次**允许这一次开放，**授予此环境**也给出它对应的端口能力以便之后的开放，**拒绝**则拒绝它。链接的审阅会说明谁会收到它的密钥。见[让智能体无需询问就能打开端口](let-agents-open-ports.md)。

## 谁能审批

| 请求 | 谁可以决定 |
|---|---|
| 智能体的命令、编辑或权限 | 会话的管理者 |
| 提出的计划 | 可以向会话发送的人，或位置把计划留给他们时的管理者 |
| 被暂缓的消息，**运行** | 可以向会话发送、并以自己的访问权使用其当前模型的人 |
| 能力 | 环境的端口管理者、主机的管理者、组织的访问管理者或系统管理员，视其范围而定 |
| 端口 | 环境的端口管理者 |
| 访问 | 能对该对象授予所请求权限的人 |
| 群组成员 | 可以把该人加入群组的人 |

对于在某一轮中发出的请求，先通知发起该轮的人（如果他有资格）。否则，只有该对象所有者行中直接列出且有资格的人才会收到收件箱条目，并在**等你处理**下看到它。当那里没有人能决定时，Orch 沿着上层位置的所有者行向上查找，再到组织的管理员，再到现在所有能决定的人。群组、角色和继承的权限不会向所有人发通知。其他有资格的人能找到这张卡片和**你也可以决定的请求**，但没有通知、未读标记和待处理计数。

## 跟随并决定卡片

在会话或[审批](/approvals)中打开请求。确认它当前的目标、受众和范围。

- 同事更早做出的决定优先。你之后的点击不能覆盖它。
- 连接丢失时，决定会被关闭，直到页面追上。
- 拒绝可以附带说明，结果保持可读。
- 一个决定会处理这个请求的所有接收者副本，并把它的收件箱条目标为已读。它离开所有待处理列表和计数，谁做了决定、结果和时间保留在历史里。这也适用于**继续执行**、**继续规划**和**运行**。
- 第二次决定会返回第一次的结果，不会再改变任何东西。如果列表无法加载别处做出的决定，它会为该结果保留一次重试，而不显示旧请求的细节。

提出的计划提供**继续执行**或**继续规划**。**继续执行**让智能体在输入框的审批模式下继续。**继续规划**把你的话发回去，让智能体修改计划。**计划**开关会在回答确认之后改变。如果回答被拒绝，原因会显示在选项旁边。在尝试一个不再提供的选项之前，请重新加载请求。

程序动作请求在程序等待期间有效。代理边界请求由 `requests.expiry_minutes` 控制，初始
1,440 分钟（一天），没有固定上限，上级最短值生效；链接可更早过期。个人访问请求初始保留 14 天。
一小时内重复同一已拒绝的代理边界请求，会返回原拒绝与附注；内容改变才是新请求。

## 再次允许例行操作

当智能体程序提供**允许此会话**时，请阅读它确切的命令或匹配的主机。它会回答此会话当前绑定中匹配的请求。它不是对另一个环境或已改变的共享登录的一般访问。**参数**列出这些规则，**撤销**可移除其中一条。问题和表单仍然等待。分叉或旁路会话不继承这条规则。

要了解管理员单独的**覆盖**，见[谁能看到和做什么](who-can-see-and-do-what.md)。
