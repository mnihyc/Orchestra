# 将线程历史带给另一个智能体

在分支或切换计划中选择**携带**，带上选定的对话。确认前先看计划中的历史传递方式。
该方式取决于目标智能体的确切版本已经通过的导入检查。

## 查看传递方式

原生导入恢复智能体程序自己的对话。中立导入按通用格式带入已记录的轮次。
文件交接向新智能体提供近期上下文，并将完整对话作为文件交给它。
计划会明确写出将使用的方式。

Codex 线程的历史保存在该程序自己的存储中，Orch 从不复制它。在创建线程的主目录里，
以及环境连同卷一起迁移时，线程以原生方式续接。原生分支还需要通过下文的轮次核对。
迁移后的环境不会在迁移时打开线程，而是在下次使用时才打开。
Codex 续接会话时，一条普通历史行会说明：它保留此会话原有的常驻指令，
指令更改将在下一个新会话中生效。这条说明不表示本轮失败。
在某一轮次处原生分支之前，Orch 会先用程序保存的对话记录核对该轮次的位置，
这份记录最多 32 MiB。超过设置**原生分支检查大小**所允许大小（默认 32 MiB，各位置可改）
的对话不做核对：计划会写**中立导入**或**文件交接**，与进入另一个主目录时相同，并明确告知。

线程进入另一个主目录时（另一个环境、另一个凭据的主目录，或没有该卷的机器），
Codex 无法把历史完整交出。若选定的全部轮次都放得进所在位置的“延续份额”
（新模型窗口的一部分），计划会写**中立导入**；否则写**文件交接**：
放得下的最近轮次逐字带入，完整对话作为文件放在工作区。
带过去的内容受窗口大小限制，而不受线程长度影响。

当程序的历史确实以文件形式传递时（对会导出历史的程序，在机器之间做原生导入），
任务会显示已到达 Orch 的字节数，以及剩余部分预计何时到达。取消任务会在机器上停止传输，
并删除它的文件。传输中途失败时，已到达的部分会在 Orch 中保留一天：线程没有改变时再次携带，
只会发送其余部分。

## 检查另一个版本

在**管理 → 构建版本**中选择**检查**，在隔离环境中验证该确切版本。
原生导入不可用时，这项能力保持关闭，并记录原因；其他检查仍可通过。
对会导出历史的程序，只有该版本确实能导出对话、在全新主目录中导入，
并读回两个已完成轮次后，原生导入才会可用。对 Codex，检查会在创建对话的主目录里
从第二个轮次分支，再在该主目录的副本中重新打开：下一次请求必须带有分支点之前的轮次，
且不含之后的轮次。修改配置档案的覆盖值不能启用尚未验证的原生导入。
