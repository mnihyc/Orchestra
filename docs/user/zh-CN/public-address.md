# 公共地址

## 更改地址

在**管理 → 系统**中输入主地址及其他地址，然后选择**保存并打开**。Orch 会准备新的受管前端证书版本，等待前端进程载入；外部边缘服务须已经能够提供同一个安装。DNS 和外部证书仍由其运维方管理。

只有准备成功后，生效版本才会变化。失败时，原地址继续生效，草稿和失败原因会保留在页面上。其他浏览器保留正在进行的工作，只显示一行可**打开**新地址的提示，不会自动重载。已开始的登录、已签发的链接和已导出的包保留开始时的地址。

示例地址状态表示尚未替换随产品提供的主地址。文件中的 `public_url` 和 `alternate_urls` 仅初始化一次系统存储；之后修改文件不会悄悄替换已提交的快照。

## 本地恢复

在能够访问部署配置和本地数据库的环境中运行：

```sh
orchctl public-address reset --config ./config/orch.toml
```

恢复已获准的文件初始值或当前集合时，不需要可用的 HTTP 主机名。全新的文件来源地址仍须完成相同的准备，才会按版本核对并重置。不会输出凭据。`orchctl public-address get --config ./config/orch.toml` 仅输出生效主地址，供本地脚本使用。

Doctor 会分别报告文件初始值和已存地址，并探测生效的浏览器页面及 API。`--url` 可选择明确的诊断路径。更新器在每次就绪检查时都会读取生效地址；`ORCH_READY_URL` 仍是运维方明确指定的路径。
