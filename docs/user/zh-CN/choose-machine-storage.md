# 选择机器保存数据的位置

每台机器都会报告它的命名存储，以及容量和剩余空间。阅读它页面上的**存储**，再在**容器配置**中使用这些名称。

- 环境的存储设置（`env.storage`）选择新的工作区、主目录和连接器状态数据存放在哪里。连接器的状态在驱动创建容器的地方有自己的存储。运行在目录上的连接器在机器上保留自己的私有数据目录，并为工作区、主目录和挂载声明存储角色。
- 托管提供方的存储设置（`runtime.storage`）选择它的主目录和状态，前提是它声明的数据角色支持这些。
- 省略的成员使用机器的默认值。机器不提供的名称会被拒绝，绝不会悄悄回退到另一块磁盘。

例如，`{"workspace":"fast","home":"bulk","state":"fast"}` 为一个环境选择了两个命名存储。提供方没有工作区，所以对它连接器的私有状态使用 `{"state":"fast"}`。提供方单独的主目录会在它的数据来源提供时使用。

存储为由 Orch 拥有的新数据选择位置。已有的目录保留它们的身份、权限和位置。Orch 已经创建的数据会保留为它记录的存储，不受重启和模板修改影响。更改存储不会移动这些数据。要移动已有环境的数据，请使用你先审阅过的移动或复制。

## 配置命名存储

节点和目录连接器都在数据目录的 `config.toml` 中用 `[[storages]]` 声明命名路径。
节点操作者也可用 `orch-node policy set storages` 写入同一份策略。
每项使用 `name`、`path` 和 `default`。路径必须已存在且位于本机允许的
`environment.roots` 中，机器先检查策略。声明的存储恰有一个默认项。

```toml
[[storages]]
name = "fast"
path = "/srv/work"
default = true
```

没有为连接器给出存储列表时，它允许的根目录提供名称：第一个根目录叫 `default`，然后是 `root-2`、`root-3`，依此类推。连接器在这些根目录之下创建它拥有的目录。没有允许的根目录就没有存储可提供。如果磁盘的顺序可能变化，请给磁盘起自己的名称。报告不会暴露连接器状态的路径或凭据。

## 替换主机模板路径

用于主机上进程的模板包含一个已存在的账号（**运行身份**）和命令，可以在多台机器之间共享。它们不再包含 `workspace_base`、`home_base` 或 `mounts_base` 路径。

1. 把旧目录声明为机器的命名存储。
2. 在环境的存储设置里选择工作区和主目录的名称。
3. 添加每个挂载卷的位置时选择一个存储。
4. 从模板中删除旧成员。

已存在的卷的记录保留它们的确切路径。应用这次配置更改时，Orch 不会重新定位、接管或清除目录。表单会解释驱动的字段。示例包含账号和命令，不需要了解某台主机的文件布局。

## 设置共同默认值

环境和托管提供方对它们共有的每个成员使用同一套结构：限制、存储、放置所需、变量、密钥名称、更新策略和启动后的命令。它们从系统开始，经资源的所属位置继承，再到它自己的值。运行时的限制包括以 GB 计的磁盘，取决于机器声明支持的配额。托管提供方没有工作区、没有用于工作的挂载、没有环境的终端或浏览器，也没有环境空闲的警告。

## 数据目录清单

机器的**存储**还显示连接器数据目录的观测结果。观测时间说明这份报告有多旧。列出的每个组成部分有它的表观大小，无法测量时显示短横线。未完成的扫描、无法读取或是链接的组成部分，以及未列出的条目，仍然作为事实可见。不可用的清单不同于已完整检查过的空目录。这些行不提供文件系统的操作对象，也不提供清理的权限。

密封存储只显示它的直接安全名称和大小。没有预览、没有**打开**、没有下载、没有嵌套文件的名称，也没有凭据值。存储容量仍是与这些文件表观大小分开的报告。
