# 将能力委派给另一个程序

线程可以通过明确选择的服务使用另一个程序的原生能力。在能力设置中选择**服务**，
再选择其委派会话后端。例如，Claude Code 线程可以请使用合适 ChatGPT 登录的 Codex
生成图像。选择后端与启用服务是两个选择；继承的默认值仍受所在位置的策略约束。
在**图像生成后端**中，先选择提供方，再选择模型和标有**服务 · Codex（ChatGPT 登录）（委派）**的路径。
仅选择提供方不会保存。不可以使用的选项会说明原因。同一个提供方与路径控件也用于搜索和页面读取，
改变其中一项不会替换另一项的后端。

使用所选提供方需要“使用”权限，模型也必须在允许范围内。请求者有权使用的任何登录都可
供助手使用，包括自己的登录，以及通过订阅共享或“使用”条目共享的登录。Orch 不检查或执行
提供方的服务条款；以这种方式使用套餐的责任由用户承担。缺少能力或套餐不适用时会显示不可用，
不会悄悄改用另一个登录。原生额度失败会保留已报告的限制和重置时间，交给既有调用恢复规则处理。

Orch 创建一个短的**助手轮次**，并从图像调用中链接到它。所有者是请求轮次实际代表的
那个人；即使登录由别人共享，所有者也不变。它是请求所在位置中的普通线程，默认仅执行者可见。
谁还能打开它，由普通线程的共享控制决定。助手的输入会链接回请求线程。

能读取请求条目的人都能看到返回的图像和助手链接。链接旁先说明程序和默认私有范围；
引用卡片会检查当前访问权限。登录的所有者能看到提供方用量，但不会因此看到助手中的提示或输入。
需要让别人查看内容时，按普通线程的方式共享助手。

只有助手实际完成的原生生成结果才能满足请求。查看过的图像、附件或文字回答不算生成结果。
图像沿用普通的保留路径，再交付到调用指定的文件。重复发布结果或重试文件交付时，
使用已保留的像素，不会再启动付费助手。写文件失败后仍保留生成的图像，可以另选目标位置。

原生用量记在所选提供方和助手轮次上，限额按请求者所在位置及图像生成用途计算。
将结果链接或复制到请求线程不会增加生成费用。模型或价格没有报告时保持未知。
取消来源会停止其拥有的初始助手工作；此后在该普通线程中独立开始的工作另行处理。
