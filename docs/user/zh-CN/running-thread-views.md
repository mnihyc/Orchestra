# 关注正在运行的线程

显示方式决定你看到多少活动，不会改变代理实际执行的工作。“专注”保留你的输入、代理回答和待处理批准，并为每轮显示摘要；“完整”还包含折叠的推理及工具行；“实时”更详细地跟随当前工作。线程会记住你的显示选择。

## 在哪里

从[导航](/)或[工作台](/workbench)打开线程。标题中有详细程度选择和线程状态。“当前”一行显示正在进行的步骤、经过时间及“停止”。深度选择可将工作折叠为步骤、摘要或全部内容。

子代理行只打开它自己的活动流；“在面板中打开”可将它放在对话旁。侧线程有独立的分栏、编辑框、队列和停止操作。主代理继续工作时，两者仍可查看；子代理没有消息输入框。

**旁路会话**向该会话的代理询问它当前的工作。想围绕当前页面或组织内容进行只读提问时，可以从侧栏打开[问一问](ask.md)。

悬停或键盘聚焦消息时可见操作行，触屏上也始终可达。你的消息提供编辑、复制及“将文件恢复到此消息之前…”，其他操作放在菜单内。代理的一轮提供复制、重试、分叉及更多操作。不可用的操作会保留原因；不支持重试的中间轮次不会提供可执行的重试操作。

## 示例

代理排查失败检查时，先用“专注”阅读进展摘要；需要观察命令时切换为“实时”。本轮出现“N 个文件更改 · +a −r · 评审”后，打开评审查看这些文件。在更改行旁添加评论，再从编辑框“发送评审”，让下一轮收到评论。

## 操作后会怎样

“更改”可以查看选定轮次、线程开始以来的更改，以及有 Git 仓库时的未提交更改。相同的文件与差异视图提供打开文件、打开差异、复制补丁、加入消息和撤销此更改，具体取决于当前权限与状态。

从视图菜单打开“后台工作”，在面板中检查此线程的原生命令和子代理。它与标题上的入口使用同一套检查列表和结束确认；“刷新”会重新读取当前状态。

后台工作运行时，其他人的输入可以使用同一会话。重叠期间的用量计入线程的首位所有者。标题会在唤醒提示及其设置旁说明这一点；各项任务和唤醒轮次仍保留最初发起它们的作者。结束任务仍需要与线程交互的权限。

即使在窄面板中，紧凑的模型控件也会在模型旁保留当前思考程度。绑定控件显示当前提供方，有权限修改时会打开原有切换计划。从 + 添加文件或可读取的文件、文档引用；选择它们不会发送草稿。

编辑框附近保留批准模式、沙箱和计划。等待批准时必须明确选择答案；按 Escape 不会拒绝请求。导航和卡片使用一致的线程状态图标。另见[恢复文件](restore-files-before-a-message.md)和[批准](how-approvals-work.md)。
