# 线程状态

## 读懂图标

线程在导航树、标签页、页头、列表和引用中使用相同的状态图标。悬停或聚焦图标，
可查看原因、等待消息数或完成时间。实时视图同步更新；搜索结果和引用显示上次读取时的状态。
树形和最近使用相同的状态图标，包括导航抽屉和窄屏下的全部内容卡片。

| 图标 | 状态 | 含义 |
|---|---|---|
| 带问号的盾牌 | 等待批准 | 批准请求、问题、计划或等待授权的消息需要有人处理 |
| 带斜线的圆圈 | 受阻 | 线程暂时无法继续，原因说明需要改变什么 |
| 带感叹号的八边形 | 失败 | 上一轮失败，之后尚未接受新消息 |
| 旋转圆环 | 运行中 | 正在准备或执行一轮工作 |
| 时钟 | 等待开始 | 消息在等待当前工作、限额或计划时间 |
| 暂停圆圈 | 队列已暂停 | 选择继续之前，队列保持暂停 |
| 带勾的圆圈 | 有新结果 | 自你上次查看后，有一轮工作已完成 |
| 对话气泡 | 空闲 | 没有正在处理的工作或未查看的新结果 |
| 归档盒 | 已归档 | 线程或其所在位置已归档 |

需要人处理的事项优先，其次是受阻、失败、运行、等待开始、暂停队列和新结果。
已归档的线程保留归档图标。只有运行图标旋转；开启减少动态效果后，它也保持静止。
两种主题都通过形状表达状态。

自动重试使用时钟图标，并显示等待时间和次数，例如“55 秒后重试 · 第 2 次，共 3 次”。
重试已安排时，无需你作出决定。恢复正在执行时显示运行图标。
自动恢复停止后，失败图标会说明原因，例如“提供方繁忙 · 5 分钟内出现 4 次”。
需要人处理的请求和占用线程的变更仍然优先显示。

## 查看新结果

完成标记代替线程的未读圆点。查看最新轮次后，你的完成标记会消失；其他读者的标记
保留到各自查看该轮次为止。提及次数仍会显示。

位置保留自己的图标，并在行末显示其中最紧急的线程状态。行末的完成标记表示内部有新结果。
无权阅读线程的人不会在私有引用中看到其状态。

队列操作见[消息队列](message-queue.md)。

## 后台工作

代理空闲时，命令或子代理仍可能在后台运行。页头在“空闲”旁列出每个已知任务的名称和状态。子代理标签仍打开其原有的会话分栏。

“这些任务结束后将唤醒代理”表示任务成功或失败后，会以启动该任务的人的身份请求继续一轮。旁边的“后台唤醒：开”显示会话接受的有效值。管理者可点击它打开这一个设置；继承、锁定和重置仍遵循普通设置规则。尚未生效的变更显示为“下次会话：开／关”。工作运行期间，会话变更会等待。

关闭后台唤醒时，显示“结果随下一次输入送达”。Codex 的后台工作仍可运行，结果随下一轮送达。Claude Code 不提供后台任务，命令在前台运行。变更在下次会话生效；每次任务结束时还会检查当前设置和原启动者的权限。

继续的轮次以“唤醒原因：构建网页 已完成”开头。多个原因以逗号分隔；失败会写成“审核认证 失败”。这些名称来自记录的任务。因权限或模型使用权限而等待的唤醒，会与其原因一起显示普通的待发输入说明。“N 个已完成任务正在等待”表示“停止”正在暂缓这些唤醒，直到下一次被接受的人工输入；它不会恢复普通的停止后待发队列。

“停止”结束当前轮次并暂缓其待发工作。“结束”原生控制一个确切的后台任务，不向模型发送指令。它需要交互权限和运行程序对该任务类型的支持。不支持时，任务显示“无法从此处结束”。结束前会重新读取原生任务列表并确认，旧任务的按钮不会误结束后来启动的工作。被人工结束的任务不会唤醒代理；未经确认的结束结果仍为未知，直到当前事实确认。

“随会话丢失”记录所属会话消失时丢失的工作。临时断线不等于已知的空列表，也不能证明任务已丢失。不会从历史记录中恢复丢失的工作。
