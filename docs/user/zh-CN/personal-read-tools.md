# 个人读取工具

## 查阅帮助

`orch_docs` 搜索英文和中文用户帮助，并给出对应文章和标题的链接。不需要启用个人读取选项。
程序须支持 Orch 工具服务器；环境或阅读模式对该服务器的禁用仍然有效。

## 允许会话使用你的访问权限

在 **设置 → 策略 → 个人读取工具** 中启用选项后，线程会获得 `open`、`search`、
`find_operation` 和 `read`。此选项默认关闭，按普通设置继承系统、组织、项目和主题的值；
继承锁定和重置的行为与其他设置相同。

这些工具与 Ask 使用同一套读取功能，以线程所有者当前的访问权限执行。它们不能写入或执行管理
操作。搜索和读取限定在当前组织内，保留原有访问检查。返回的内容是需要判断的资料，不是指令。

共享会话后，选项仍保持你设定的值。每次调用仍检查选项、所有者当前的读取权限和组织。
`list_shared`、`read_shared` 和 `search_shared` 继续用于明确共享给智能体的资料。

只要所有者以外的人能够查看或操作会话，单行受众提示条就会简要统计人员、角色等受众类型。
打开提示条可查看完整名称和谁能发送；点击 **共享** 可打开现有共享设置。只有个人读取已开启时，
提示条才会说明以你的权限读取的内容对受众可见。选项关闭或尚未读取时，不会作出这项说明。
受众随授权变化更新，包括空群组和未来的智能体；仅有“交互者”等角色名称不代表能够发送，
发送资格由会话实际的交互或管理授权决定。

关闭提示条表示你已知晓当前受众；本设备会按人员和会话记住这项选择。
出现新的受众，或有人获得发送权限时，提示条会再次出现。关闭后，**参数**检查器中的个人读取状态仍然保留。

**参数**检查器显示个人读取在解析后的设置中是开启还是关闭，并列出共享读取工具。
如果无法读取当前设置，会明确说明，不会将未知状态显示为关闭。

## 共享线程已经读到的内容

添加读者、权限页条目或智能体共享可能公开先前的个人读取结果。应用更改前会提示：
“此线程包含 N 条使用你自己的访问权限读取的结果；共享对象将能看到这些结果。”
取消会保留原来的访问范围。确认后，这些结果将与其余历史一起共享，包括智能体根据它们作出的回答。
没有此类结果的线程不会显示提示；结果数量有变化时，需要重新确认。

共享后，已启用的个人读取工具仍保持启用。读取结果和智能体据此作出的回答对会话受众可见。
先前已接受的结果仍属于会话历史；后来撤回访问权限，不能收回他人已经读到的信息。
