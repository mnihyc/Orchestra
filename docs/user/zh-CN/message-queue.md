# 消息队列

## 1. 找到等待运行的消息

等待中的输入统一显示在输入框上方的队列中，包括第一条输入，以及被停止、限额或线程
阻塞留住的消息。队列折叠时可点击标题展开。每行显示第一条有意义的内容，悬停或聚焦
可查看完整预览。

## 2. 修改或移除消息

对自己写的待发送消息选择**编辑**，用按钮或 Ctrl+Enter 保存，macOS 使用 Command+Enter。
取消会保留原文，附件不会因编辑文字而丢失。有权操作线程的人可以移除待发送消息。
被留住的消息仍可编辑、移除，不必因为线程暂时无法运行而丢掉草稿。
普通消息开始投递后，行上会显示**发送中**，不再接受待发送内容的修改。
正在投递的引导消息有单独的**正在引导…** 状态，见下文。

## 3. 决定何时交给代理

代理运行时，Enter 或发送默认会排队。Ctrl+Enter（macOS 为 Command+Enter）请求引导。
所在位置的**默认投递方式**设置可以改变默认选择。

- **排队**等待当前一轮结束。
- **引导**在代理支持时，把输入交给正在进行的一轮，不停止它。
- **中断**停止当前一轮，并让这条消息排到最前。

**立即发送**把消息放到最前，运行中会在支持时使用引导。如果按钮显示**立即中断**，
它会停止当前一轮；请确认这是你的意图。不支持引导时会显示原因，可明确选择中断。
这些动作都不能绕过限额、权限或阻塞的配置。停止操作留住队列后，准备好继续时使用
队列的恢复动作。
如果停止时轮次仍在启动，尚未交付的输入也会留在暂停的队列中。
如果轮次开始前会话丢失，线程会显示失败原因，输入会返回队列。
多次启动失败后，输入会保持失败状态。否则，准备继续时可发送另一条消息；等待中的输入会先运行。
原消息仍在等待时，轮次页脚会提示它在输入框上方的队列中，不会再创建一份副本。
如果队列已折叠，点击队列标题即可查看消息。

## 4. 调整顺序

通过拖动手柄移动待发送行，使用上下箭头，或先聚焦该行，再按 Alt+Up / Alt+Down。
快捷键会重排消息，不会切换会话。可用操作取决于权限，只有作者能编辑自己的文字。
操作失败时阅读错误后重试，不必再写一条重复消息。

## 5. 把未接收的引导消息放回队列

引导消息会在队列中显示为**正在引导…**。在 Orch 开始把它交给程序前，可以选择**放回队列**。
消息会回到等待消息中的原位，保留原文和作者。显示**代理正在接收此消息**后，就不能放回。
程序接收后，会话中显示**已引导**。

如果轮次在引导消息交付过程中结束，Orch 会等待结果，再开始下一轮。
确认接收的引导消息属于接收它的轮次；被拒绝的消息会回到队列最前面。

放回消息不会撤销代理已经做过的工作。之前的消息已经被接收时，请再发送一条修正消息。

折叠文本和私有附件的用法见[粘贴与上传](paste-and-upload.md#pasted-text)。

## 等待模型或环境使用权的消息

能读写线程不等于能使用它的模型，也不等于能使用它所在的环境：发给智能体的消息会让它
代发送者在那里行动，所以发送需要线程的“交互”权限、提供方及其模型和推理强度的“使用”
权限，以及环境的“使用”权限（**使用环境**）。默认的待批准策略会保留输入的队列位置，
显示**等待可以使用该模型和环境的人**（线程不在环境中时只等模型）。其他符合条件的输入
可以先行。你仍可按普通规则编辑或移除自己暂存的输入。

引导消息会检查当前运行轮次所用的提供方、模型和推理强度。更改后的模型设置从下一轮开始生效。

有权驱动线程、并能使用当前提供方、模型和推理强度以及其环境的人可以选择**运行**。这一轮按
批准者当前的权限和用量运行，保留原作者，并记录批准行为。动作会重新检查批准者
权限，不能借用发送者权限。

一人运行后，各处请求卡片都显示决定者和时间，不再计入待处理或未读。再次尝试会显示已经记录的结果。
谁会收到通知、谁有权决定，遵循[审批规则](how-approvals-work.md#who-can-decide)。

位置也可以选择拒绝，在发送前说明缺少的使用权；或允许，按线程第一位所有者检查。
这些选择由可锁定的 `thread.inputs_without_use` 控制。授予提供方或环境权限与
批准一条暂存输入是不同的动作。
