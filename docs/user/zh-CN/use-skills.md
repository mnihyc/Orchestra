# 给代理提供有版本的技能

## 导入技能

打开资源 → 技能 → 添加技能，选择压缩包、Git 仓库、地址、环境目录或新草稿，
再选所属位置。技能包含 `SKILL.md`，也可包含参考资料、脚本和其他文件。

压缩包可选择内部子目录。Git 和地址导入使用你选的主机；Git 还要填写版本及可选子目录。
目录导入使用你有权管理的环境。这些操作把版本复制到 Orch，之后使用不依赖原环境。

脚本是可执行内容。开放技能前应检查来源和文件。私有来源凭据保持密封，
读取技能不会得到凭据值。

## 检查并发布

概览显示最新版本、来源、作者、时间和大小。版本页可打开以前的不可变版本和文件。
文本以只读方式打开，二进制文件保留元数据。

用**从来源更新**再次导入；**添加版本**可使用另一个压缩包或来源。来源无变化时会显示已是最新。
编辑时打开草稿，从当前版本开始，保存文本或上传替换文件，并按需设置脚本可执行位。
发布生成新版本；丢弃移除草稿。未发布的草稿不会交给其他线程。

## 启用已发布版本

在位置设置的技能（`agents.skills`）中添加你有权使用的技能。选择最新以跟随发布，
选择编号版本以固定，或选择关闭停用该项。继承和锁与其他设置一致。
是否允许线程发起者加入自己的技能，由独立的个人技能策略决定。

技能的访问页区分使用与管理。使用允许启用可用技能，管理允许改变内容和版本。
仅能查看资源不具有这两种权限。关闭技能会停止提供它。

## 知道变更何时到达

启用的已发布版本在下一轮前到达线程。空闲会话可在后台刷新；刷新尚未结束时，
到达的输入显示**正在更新技能**。每一轮都记录实际使用的版本。

技能交付属于线程自己的会话及命令环境，不写入提供方的共享主目录。启用技能不会
增加文件、网络、模型或工具权限；执行仍受线程原有边界和审批约束。
