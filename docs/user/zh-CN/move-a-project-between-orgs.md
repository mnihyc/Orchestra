# 在组织或部署之间迁移项目

**Orch 包**是 Orch 能再次读取的导出文件。把一个位置导出为包，再把文件导入到你有权创建内容的任何位置：
另一个组织、另一个项目，或另一个 Orch 部署。导入会先显示它将做什么，并且不写入任何内容；
你确认之后，它作为一个任务运行，可以查看进度、取消和撤销。

## 导出项目为 Orch 包

在组织、项目、主题、会话、聊天、文件夹或文档上打开**导出…**。在**形式**中选择**Orch 包（可再次导入）**。
文件与评论默认开启；是否包含版本由你决定。

包是一个 zip 文件，含有结构（位置与文档文件夹）、文档及其文件，以及你所选的评论和版本、聊天，
以及作为历史记录的会话。每一项都有 Orch 可再次读取的记录和便于阅读的 Markdown 副本。
文档还包含保留布局、链接到旁边文件的 HTML 副本。清单列出每个部分及其校验值，所以导入时能发现损坏或被改动的文件。
导出限制排除的内容也会在清单中列出，并附上原因。

包中出现哪些人，与其他导出的规则相同：人员以名称和用户名出现；只有系统管理员导出时才会写入邮箱地址。
只有你管理其访问权限的位置和文档，包才会带上谁能看到什么、做什么。

## 导入 Orch 包

在组织、项目、文件夹或主题的菜单中选择**导入…**，或在文档列表中选择**导入**。共五步：

1. **来源**：拖入包或选择文件。Orch 根据清单识别包。
2. **目标**：选择位置；如果包是由某个位置生成的，还要选择让它作为所选位置内的新位置，还是放入该位置。
3. **预览**：试运行。显示数量、相对限制的大小、每个对象将采取的操作、人员、冲突和损失。
   在你选择**导入**之前，什么都不会创建。
4. **导入**：一行实时状态，显示阶段（检查、匹配、创建、报告）、项目数和已用时间。
   可以关闭对话框，任务会在状态栏中继续。**取消导入**会停止任务；已创建的内容保留，报告会如实说明。
5. **报告**：每个对象一行（已创建、已保留两者、已替换、无变化、已跳过、失败），并用文字说明原因，
   可下载为 JSON 或 CSV。设置中的**你的导入**会保留这些报告。

即使导入在写入任何对象记录之前就失败，报告仍会显示失败的原因。

你只能导入自己在该处手工能创建的内容。你无权创建的内容，或不能放在该位置的类型
（例如文档已关闭的位置里的文档、文档文件夹下的聊天），会连同原因显示并被跳过；其余内容照常导入。
每一批创建前都会重新检查你的权限，所以长时间导入期间角色变化会被遵守。

包中的组织会作为项目导入；组织自身的设置、成员和共享不属于导入可创建的内容。

## 人员会怎样

包中出现的每个人按以下顺序匹配，先匹配到的为准：相同的账号 ID（来自本部署的包）、已确认的邮箱地址、
用户名、你在**人员**标签页中的选择，最后是**导入的人员**标签。匹配从不创建账号。

**按账号**会把包中记录为某账号所写的内容写成该账号所写，仅向该位置的管理员提供。
**以我的名义，保留原作者**让你成为所有内容的作者，并在内容能显示的地方保留原名：报告中、聊天消息或评论开头、
以及对象本身会写明“原作者 …”。不是该位置管理员的人使用这种方式，也是更安全的默认选择。

## 冲突与重复导入

导入的对象与已有内容相遇时，有两种识别方式。

- **同一来源**：该内容之前已由同一个包或同一位置的导入带入。默认**替换**：文档会新增一个版本并保持原有身份，
  指向它的链接继续有效；没有变化的内容保持不动。聊天和会话会合并：之前已有的消息不会重复，新的会被加入。
- **同名**：同一位置有另一个同类型、同名称的内容。默认**保留两者**：新内容会使用空闲名称，例如“笔记 (2)”。

**冲突**标签页为每种相遇设置默认操作；某一行自己的选择优先（**创建**、**保留两者**、**替换**、**跳过**）。
跳过某个位置或文件夹，会同时跳过其中的内容。把同一个包导入到同一个位置两次，第二次除包中后来改动的内容外不会有任何变化。

导入内容之间的引用、提及、文件链接和相对链接会一次性改写为新位置。指向包外内容的引用只保留其文字标签。

## 哪些内容不会恢复

Orch 包是工作的副本，不是运行中系统的副本。以下内容不会恢复，**不会导入**标签页会在开始前说明：

- 智能体程序的原生会话（会话以历史记录导入，不绑定任何环境）；
- 工作区与其他环境文件；
- 密钥；
- 用量与审计记录；
- 个人自己保留的内容（已读标记、置顶、草稿）和审批；
- 存放在网络上的图片（仍为链接）。

导出时被排除的内容（过大、不可导出、无权限）以及导入后有改动的内容，都会连同原因一起计数。

只有包中带有共享设置、**共享**开关已打开、并且你在目标位置拥有管理权限时，共享设置才会恢复。
包中提到的每个人会在导入所创建的内容上，按你手工授予的方式重新获得原有权限：你无权授予的、
由上层锁定决定的、该位置不允许指名的人，以及在这里没有账号的人，都会被略过并计数。
原本就在那里的内容保持它自己的共享设置。

## 撤销导入

报告中的**撤销导入**会先显示计划：此次导入创建了什么，以及因为之后有人在其中添加内容或做过修改而会保留的内容。
如果当前检查阻止撤销，对话框会显示原因。没有阻碍时，确认只会按通常方式删除此次导入创建的内容，
所以在所示日期之前仍可恢复。被别人修改过的文档会保留；之后写在导入所创建的位置或文件夹中的内容也会保留，
容纳这些内容的位置和文件夹同样保留。只会删除你现在有权删除的内容。导入时替换过的已有内容不会回滚；新版本仍留在它们的历史中。

撤销后，报告仍可查看和下载，但不再提供打开已删除位置的按钮。

撤销后可以再次导入同一个包。新的导入会创建新副本，被删除的副本仍可恢复。
对新副本再次导入时，其身份保持不变。

## 导入纯文件

同一个向导也可以导入并非由 Orch 生成的文件。**文件**可导入 Markdown、HTML、Word 和文本；
**文件夹**会把文件夹保留为文档文件夹；**压缩包**可导入这些文件及其图片的 zip，或 tar（`.tar`，以及用 gzip、bzip2、xz、zstd 压缩的 `.tgz`、`.tar.gz`、`.tar.bz2`、`.tar.xz`、`.tar.zst`）；内含其他 zip 的 zip（Notion 导出即如此），或一起选择的多个 zip，会被当作一个整体读取。
文件之间的相对链接和图片会指向新的文档和附件；找不到的文件会在报告中列出，文本中的链接保持原样。

一次导入可带入的数量由运营人员设置；除非另行设置，它们与导出可容纳的数量一致。

## 设置导入的线程

打开线程即可阅读导入的消息。在输入框中选择 **选择代理**，再选择提供方、代理、模型和环境，点击 **设置**。
导入的消息保留为历史记录；下一条消息将使用所选配置开始本地工作。
标题下方标明**导入的历史记录**。**尚未设置**表示尚未选择本地智能体；
标题中的**选择智能体和提供方…**会打开同一个设置对话框。
文档、块和已保存版本与评论及消息采用相同的人员映射。文档的所有者仍是导入者。
