# 审批如何工作

请求说明将发生什么、谁能决定及每个选择允许什么。回答前阅读后果。
环境内部的工作和改变环境边界使用不同的权限。

## 环境内部的工作

代理程序请求运行命令或修改文件，需要有权管理线程的人决定。审批模式只作用于现有
环境边界内的工作。**按请求**在程序认为需要或文件规则阻止动作时询问；
**询问**会在程序尚未信任的动作前请求。

新对话优先使用所在位置的审批模式，前提是所选代理程序支持它。否则使用程序的默认模式，
例如 DeepSeek Harness 的**询问**。所在位置允许的模式和环境边界仍然生效。

**自动**使用代理程序自己的审阅器。只有真实试用证明该程序和提供方的模型、权限及行为
符合要求后才开放。允许的动作运行，拒绝的不运行，线程保留模型和结果。自动从不作为
默认；审阅器可能用另一个模型并消耗额度。单独报告的用量归该线程，否则包含在程序总量中。

**绕过**：代理在其环境中执行任何操作都不再询问；选择者对此负责。
它需要另有隔离边界且程序以非 root 身份运行。问题和提议的计划仍需你回答。

例如按请求的线程可运行普通测试，然后请求写受保护文件。允许一次只回答这一请求。
“应使用哪个分支？”这样的提问在任何模式都要由人回答。

## 改变边界

KVM、端口和访问请求需要对将开放对象的实际权限。管理线程不允许授予别人的主机 KVM、
开放端口或提供别人的模型凭据。卡片显示真正的决定者。绕过、自动、线程规则和停止都
不能替这些请求作决定。

能力策略可以允许、询问或拒绝。允许时记录所依据的策略。端口的**允许一次**只准本次开放；
**授予此环境**也准许以后匹配的开放；**拒绝**不开放。链接审查说明谁会收到秘密。
详见[让代理无需询问即可开放端口](let-agents-open-ports.md)。

## 谁能审批

| 请求 | 有权决定的人 |
|---|---|
| 代理命令、编辑或权限 | 对话管理者 |
| 提议的计划 | 能驱动对话的人；当前位置要求管理者回答时，仅管理者 |
| 待运行消息的“运行” | 能驱动对话，并能使用自己当前权限访问所选模型的人 |
| 能力 | 按请求范围，由环境的端口管理者、主机管理者、组织访问管理者或系统管理员决定 |
| 端口 | 环境的端口管理者 |
| 访问 | 能在该对象上授予所需权限的人 |
| 群聊成员资格 | 能把该申请人添加进群聊的人 |

轮次内提出的请求优先告知有权审批的轮次发起人。其他情况下，只有对象“所有者”行中直接命名且有权审批的人
会收到收件箱通知，并在“等待你审批”中看到它。如果没有合格的人，依次向上找所在位置的所有者、组织管理员，
最后找当前所有有权审批的人。群组、角色和继承权限不会让所有人都收到通知。
其他有权审批的人可以从卡片或“你也可审批的请求”处理，没有通知、未读标记或待处理计数。

## 跟随并决定卡片

在线程或[审批](/approvals)中打开请求，确认当前目标、接收范围和作用域。别人先回答时，
你的晚到点击不能覆盖。断线后决定要等待页面追上当前状态。拒绝可以附注，结果仍可阅读。

一人决定后，所有收件人的卡片都会处理完毕，收件箱项目标为已读，请求离开待处理列表和计数。
谁做了什么、何时决定仍留在历史里。“执行计划”“继续规划”和“运行”也一样。
第二次决定返回先前结果，不会重复运行或授权。
如果列表无法读取其他人做出的决定，会保留重试入口，不显示旧请求的详情。

提议的计划提供**执行计划**或**继续规划**。执行计划后，代理程序按输入框中的审批模式
继续工作；继续规划会把你的意见交给代理程序修改计划。答案确认后，计划开关才会更新。
答案被拒绝时，原因直接显示在选项旁；如果选项已失效，请先重新加载请求。

程序动作请求在程序等待期间有效。代理边界请求由 `requests.expiry_hours` 控制，初始
24 小时，可取 1–168，上级最短值生效；链接可更早过期。个人访问请求初始保留 14 天。
一小时内重复同一已拒绝的代理边界请求，会返回原拒绝与附注；内容改变才是新请求。

## 再次允许例行动作

程序提供**允许此线程**时，检查精确的命令或主机匹配条件。它只回答本线程当前绑定下
匹配的请求，不开放另一个环境或变更后的共享登录。参数面板列出规则，**收回**可移除。
问题和表单仍等待回答，分支或侧线程不继承规则。

管理员独立的越权操作见[谁能看和做什么](who-can-see-and-do-what.md)。
