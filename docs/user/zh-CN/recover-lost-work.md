# 机器丢失后恢复工作

## 声明丢失

主机、环境或机器不会再回来时，在其 **⋯** 菜单选择**声明丢失…**。主机或环境由其管理者操作；个人机器由机器主人操作。

先查看受影响的环境、线程、保留数据、挂载、提供方运行时和任务。无权查看的工作只显示数量。选择是否**通知**，输入完整名称，再确认。Orch 会永久撤销受影响的机器身份，不向丢失的机器发送清理命令。依赖它的任务以**丢失**结束。

线程保留对话和环境绑定。提示栏说明环境已丢失，并提供**在别处运行…**。从未确认送达的输入保持失败，由作者决定是否重试。

## 恢复环境

从丢失资源的菜单或收件箱条目打开**恢复…**，也可同时选择多个环境。仍在响应的主机提供**全部移动…**，使用同一个审核界面。

选择共同的**目标主机**，或保留**自动**。每一行也可选择其他主机。你需要管理该环境，并且自己有权使用目标主机和模板。不归你管理的环境只显示数量，由其主人恢复。

为每行选择操作：

- **移动**复制仍在响应的环境，保留同一个环境及线程。本机代理可从复制的主目录继续。主目录无法迁移时，使用记录的对话和 Carry 交接继续。
- **重建**重新创建丢失环境的运行单元。页面、主人、设置和线程不变。审核会检查已恢复的工作区和主目录卷；否则只复制 Orch 仍持有的文件内容。确认前查看缺失文件数量。**文件列表不可用**表示覆盖范围未知。
- **切换线程**把线程送到下文选择的目标环境。

计数在后台运行。必需计数和当前审核就绪后才能确认。未知大小显示 **–**。受阻的行不会阻止其他可执行行运行。同一个进度界面显示各自独立的任务。**重试失败项**选择失败或丢失的成员。取消会保留已完成的工作。

管理员需明确选择现有的管理员操作。审核列出将添加的权限，审计记录此次绕过。

## 选择切换目标

**目标环境**可选择已有环境，或为整个批次创建**一个共享新环境**。创建时可填写名称并选择主机。普通线程批次也可保留各线程原来的环境。丢失、已移除或停用的环境不会成为目标。

确认前审核目标和文件复制的后果。即使各线程保留原有提供方和模型，批次仍使用这里指定的环境。

## 通知受影响的人

每次确认都有自己的**通知 N 人**选项。「操作通知」（`notify.operations`）决定默认值：阻塞工作时开启、始终开启或始终关闭。确认前可以更改选项。该设置遵循所属位置和系统锁定。跨多个位置恢复时采用系统默认值。

数量只包括按各人通知设置会收到这一类通知的人。悬停、聚焦或点击数量可打开统一的人员列表，显示你有权看到的姓名，其余只显示数量。选择人员可打开名片。每位接收者只收到一个汇总该操作相关工作的收件箱条目，更新也留在该条目中。关闭通知便不会生成该条目。

在**设置 → 通知 → 类别**选择你接收的类型。更改会自动保存；保存失败时会显示原因。这里更改你自己的选择，别人操作中的通知选项不会替你开启已关闭的类型。

## 服务器与挂载

导入的 MCP 服务器在机器丢失或删除后，保留定义、设置和权限。没有其他就绪来源时，页面显示**没有机器**。

后来加入的机器只有报告相同名称和定义，才会立即再次提供同一个导入项。定义包括传输方式、命令或地址，以及环境变量名；不比较变量值或秘密值。页面显示来源及提供时间。不同定义保持**发现**状态。服务器管理者还需有权从该机器导入，才能选择**使用该机器的定义**并记录新定义。仅发现服务器不会启用它。

挂载在没有当前位置时仍保留定义和启用选择。丢失位置显示**丢失**和最后已知大小；从未计数则显示 **–**。先在其他主机添加位置，才能在那里挂载。Orch 不会尝试清理丢失的机器。

挂载内容检查依赖的任一机器被声明丢失时，检查以**丢失**结束，不会自动开始下一次读取。所需位置可用后，明确选择**检查**才能发起新的比较。

## 提供方运行时

提供方的运行时丢失后，保留设置和权限，运行时文件不可用。管理者可在运行时配置选择**重建**，审核目标和通知选项，再确认。只存在于旧机器上的凭据可能需要重新登录。

## 移除主机

**删除…**一起审核环境、挂载位置、MCP 服务器和提供方运行时四组依赖。环境默认先恢复；改为移除时使用其通常的保留数据期限。你只能更改有权管理的环境。

每项挂载数据都有自己的选择：**留在机器上**、**移动**或**删除**，默认留在机器上。移动使用通常的复制传输，在另一台主机建立新位置。需为它选择目标主机。Orch 接收的既有目录始终保留，包括复制之后。删除需输入挂载的完整名称。早先保留的副本各有一行。

已移除环境的文件默认**等待至**原有日期。当前所属位置的管理员可选择**立即清除**并输入环境名称。其他管理者可在到期后清除。删除或重试本身不会缩短日期。

**清除此处由 Orch 管理的内容**默认开启。计划列出自有单元、镜像、构建、网络和工具版本及其大小，排除选择留存或等待的数据。没有逻辑所有者的卷和层有单独的留存或输入名称后删除选项。清单不完整时不能清除。未知大小显示 **–**。

该主机停止提供 MCP 服务器，导入的资源仍保留。提供方默认保持不可用，也可选择在别处重建。

查看阻碍和保留期限，选择通知，输入主机名称，再确认。主机暂停接收工作，任务先执行你有权处理的部分。他人的环境不会阻止开始。进度行说明剩余的恢复操作、需要由其管理者恢复或移除的环境，或等待保留数据的具体日期。等待期间取消会保留主机登记；已接受的级联操作继续。

结果列出机器上留下的对象及大小。丢失主机只从 Orch 移除。机器可访问后，在其上运行 `orch-node uninstall --purge`，审核并移除剩余的自有对象。

## 默认环境丢失时

丢失或已移除的默认环境不再接收新线程。Orch 使用通常的环境选择回退。选择通知时，受影响主题的管理者会收到另选默认环境的提醒。

丢失、已移除或正在从丢失状态恢复的环境不能用于新线程。请选择其他环境，或等待恢复完成。
