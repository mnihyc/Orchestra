# 智能体程序版本

Orch 的每个版本都附带每个内置智能体程序的一个默认构建，版本说明里写明了它们。本页说明如何阅读 Orch 检查过的内容、选择运行哪个构建，以及如何更改它。

打开**管理 → 智能体程序**。按程序的名称或标识符搜索分页的列表，然后选择它。

- **构建**列出它的各个版本及其检查。
- **能力**按组列出所报告的构建支持什么，每项不可用的功能旁边都有原因。
- **设置**保存版本策略、它解析到的构建，以及它在哪里使用。选择使用数量，可以看到持有该构建的环境和托管提供方。

默认构建和检查过的最新构建是两回事。更改默认值不会改变随版本附带的构建。Claude Code 的**跳过提示**还允许不经询问的危险删除；见[审批如何工作](how-approvals-work.md)。

## 兼容性检查

Orch 在后台检查构建，从不在会话启动时检查。每个构建只检查一次，因为构建从不改变。**检查**会再次运行检查。

1. 它首先检查 Orch 用来驱动该程序的接口。
2. 然后在隔离的容器里，用脚本化的模型运行该程序自己的测试用例，容器没有外部网络，也没有模型凭据。

选择状态可以阅读缺少的接口名称、失败的用例和关闭的功能。用例会说明它证明什么，例如**运行命令前会询问**。关闭的功能会说明这个构建带来了什么变化，以及使用哪种后备。检查器的诊断信息保留在下面。

| 状态 | 含义 |
|---|---|
| 正在检查接口… | 正在读取程序的接口 |
| 正在检查兼容性… | 正在运行程序的测试用例 |
| 已检查 | 检查通过，或版本发布时已认证这个构建 |
| 已检查 · N 项检查待运行 | 已运行的检查通过了。之后的版本增加了 N 项尚未运行的检查。它们会在后台自动运行，在此期间，这个构建已经表现出的任何能力都不会被拿走 |
| 未测试 | 没有检查完成。结果会说明缺少什么 |
| 失败 | 有检查失败了。关闭的功能最先显示，它的用例在结果里 |

可选且失败的功能在这个构建上不可用；其他功能仍然工作。无法运行的检查不算失败。这发生在没有可以运行它的主机时，或主机的节点是较早的版本、缺少这项检查时。构建保留它上一次检查所显示的内容，没有运行的检查会这样说明，并等待能运行它的主机。更新方案会对未测试或失败的目标发出警告，运维人员仍然可以选择它。校验和不匹配的构建会被拒绝。

**导入历史。** 程序能否自己导入历史，是逐个程序检查的。对导出历史的程序，检查会导出一个简短的会话，并把它导入程序的一个全新主目录。Codex 在自己的存储里保存会话的历史，所以它的检查会在创建该会话的主目录里，从某一轮分叉出一段简短的对话，并在该主目录的一份副本里重新打开它。

如果构建没有通过这项检查，**延续**会指出这个构建，并说明程序自己的导入不可用。这时切换会在有中立导入的地方使用它，把对话作为条目带过去。当它也不可用，或历史放不下时，最近的历史放进交接通知，完整的对话作为文件提供。延续不会被阻止。配置不能重新打开构建的检查已经关闭的导入。

Codex 会话在创建它的主目录里，以及随环境一起移动的主目录里，用它自己的历史恢复和分叉。进入另一个主目录时，**延续**会带去能放进新模型窗口的延续份额的最新轮次，以及作为文件的完整对话。恢复 Codex 会话会保留它原来的常驻指令；对它们的更改在下一个新会话里生效，这不会让某一轮失败。

## 选择策略

| 选择 | 它选中的构建 |
|---|---|
| 发行版默认 | 随版本附带的默认构建 |
| 最新已检查 | 检查通过的最新构建；否则是随版本附带的构建 |
| 最新（未测试） | 已发布的最新构建，附带它真实的检查状态 |
| 精确 | 你指定的版本 |

**精确**提供 Orch 已知的版本。输入另一个版本并选择**获取并检查**。Orch 读取该版本声明的来源位置，验证它缓存的内容，并在后台运行检查。没有允许运行检查的主机时，构建保持**未测试**并给出原因。检查结束后，选择**使用版本**，它会保存**精确**这个选择。只选择**精确**会保留一个草稿，直到你使用这个版本。不可用的版本会说明原因；Orch 绝不会用另一个版本代替它。

## 固定版本与继承

策略由系统设置。组织可以覆盖它，然后是项目或文件夹，再然后是环境在它自己的**设置**里覆盖。上层的锁会阻止下层的覆盖。每个程序的选择是分别继承的。

- **智能体配置的精确版本**优先。会话绝不会在与它配置的固定版本不同的版本上启动。如果环境里是另一个构建，请更新它，或选择匹配的配置。固定版本互相冲突的配置，不能在同一个容器里共用一个程序的安装。
- **继承**会在这里移除一个程序的固定版本，并保留其他程序的选择。**随附**是有意选择随版本附带的构建，它可以与上层的策略不同。

**某个人已连接的机器**保留它的所有者安装的程序。Orch 显示报告的版本，所有者在那里升级或降级。Orch 还会读取这类机器所报告的每个程序的发布渠道，并自己检查主机上的最新构建。所以程序更新到的构建会在发布后不久被检查，在检查完成之前它显示**兼容性未验证**。

- 更新的构建，不论它属于哪个系列，都保持这些功能可用：编辑已发送的消息、从它的较早版本继续、从 Orch 结束后台命令，以及网络搜索的记录。
- 编辑和继续（Claude Code）、结束后台命令和引导运行中的轮次（Codex），以及**自动审查**（Codex），对未检查的构建保持开启。只有当对这个确切构建的检查让它失败时，它才会关闭，构建页面会指出它。当较新的构建改变了其中之一、而还没有检查显示它时，这个操作会以程序自己的错误失败。
- 经过测试的系列里的构建是**受支持**的。较新的系列显示**兼容性未验证**。
- Codex 程序自己的历史导入，需要这个确切构建的检查通过。没有通过时，对话作为条目带过去。
- 比 Orch 测试的最旧构建更旧的程序不会启动。版本说明会指出那个构建。

环境会写出它报告的每个程序，即使它的构建在目录里没有检查。未知的检查会写**检查不可用**，名称从未声明的程序会写**未报告程序名称**。

## 升级和降级

修改策略不会改变正在运行的单元。**有可用更新**表示单元持有的版本
与现在新建时会获得的版本不同。变更会列出前后版本，并标明**较新版本**或**较旧版本**。对于 Orch 自身的连接器和工具，变更列出发行版本（如 0.1.2 → 0.1.3）；只有同一发行版本的构建不同时，会说明有较新的构建，构建号和校验和不会显示。运行定义发生变化时只说明已变化，其校验和在“复制 ID”之后。

对于一个环境，请在它的设置里把**精确**设为你想要的较旧或较新的构建，然后选择**更新…**。确认之前，请阅读目标的检查、什么会保留、什么会停止，以及受影响的会话。

对于多个，请选择环境或提供方，然后选择**更新…**。主机的**容器**标签页一起更新它的容器。**智能体程序**里的**更新 N 个环境…**会选中处于自己的策略之后的容器。方案会列出被跳过的容器及原因。每个被接受的容器都有自己的作业和自己的退路。

当主机或程序同时有两个池时，请选择**更新范围**：环境或托管提供方。审阅并确认每个池的批次。它的进度在**隐藏**之后继续。选择另一个池会显示一份新的方案，带有它正在运行的轮次。

## 正在运行的回合

方案提供**等待**（带有分钟数）或**立即中断**。**立即中断**是强制的选择。方案会统计它影响的运行中轮次。一个选择适用于批次里的每个成员，它的初始值来自更改的设置。

**通知 N 个人**会为整个批次向每位受影响的人发送一条收件箱条目。打开数量可以看到这些人。通知写出是谁要求更新，统计受影响的会话，并打开受影响的工作。

更新会保留环境的持久文件和对话。方案会写出结束的任何进程或可写层的更改。它的**失败时**一行说明之前的容器如何回来。确认之后，请跟随作业的进度。隐藏对话框会让它继续运行。

## 镜像和离线版本

当无法连接到供应商的主机时，请设置**发布镜像**。镜像在它自己的地址下提供供应商的主机和路径。精确的获取使用同一个镜像。对要求更新构建的策略，以及对已连接机器报告的程序，发布渠道按计划读取。发布检查间隔为零会关闭这个计划。

管理员也可把构建文件复制到内部文件服务器，再在程序管理页中填写其 URL 和 SHA-256。
现有的构建注册接口接受同样的信息。随后运行**检查**。
新节点按当前发行版随附的配方准备隔离检查镜像，此后复用普通镜像缓存。
如果主机配置为禁止构建，可以使用已明确配置的可信预加载检查镜像。
检查本身无法访问网络、共用的主目录或提供方凭据。

## 内置程序

- **Codex。** 它的接口检查会检验 Orch 所用的应用服务器的模式。
- **Claude Code。** 它的接口检查会检验 Orch 所用的命令行标志。导出 Claude Code 会话的历史之前，请先暂停它。Orch 以流的方式处理大的归档，如果在它复制期间源文件发生变化，就会拒绝导出。
- **DeepSeek Harness。** 它使用 Agent Client Protocol。它的检查也会验证 Orch 提供的配套功能。不可用的附加功能不会隐藏该构建的其他能力。
