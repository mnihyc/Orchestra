# 按所属位置和来源组织资源

资源分组使用已有事实：所属位置、所有者、机器和标签。显示分组不会创建新资源或授予权限。资源所属位置承载共享策略；来源机器说明它从哪里来，或能在哪里运行。容器的机器以其所在主机称呼：保存在容器中的资源会显示“来自 主机名 上的容器”，同一主机的容器归为一组。

## 在哪里

打开[资源](/resources)及其中一种资源列表，在排序旁选择“分组 → 所属位置 / 所有者 / 机器 / 标签 / 不分组”。初始按所属位置分组，每个列表会在本设备记住上次选择。[所有内容](/everything)也会将资源列在所属位置下。

资源选择器按可读取的所属路径分组，当前工作位置的组排在前面。输入名称可跨组缩小范围；方向键跳过组标题，在选项间移动；Enter 选择可用项。遇到不可用项时，可先查看原因，再选择其他项。

## 示例

将主机 A、B 的所属位置设为 Guests 项目，并通过该项目的共享策略授予相应人员使用权限。在[主机列表](/resources/hosts)按所属位置分组，就能一起看到它们。另在[MCP 服务器列表](/resources/mcp)按机器分组，查找从 Workstation 导入的副本。

## 操作后会怎样

从机器导入或在机器上创建的资源，初始沿用该机器的所属位置。管理者可以用“移到其他所属位置”覆盖这个默认值；再次导入或注册会保留此项明确选择。

切换显示分组不会移动资源。改变所属位置不会搬迁文件，也不会改变机器限制。导入的 MCP 定义仍只属于原来的机器。[导入和使用 MCP](mcp-import-and-use.md)及[切换和搬迁环境](switch-and-move-environments.md)说明相应操作。

## 资源池

在资源分组上选择“创建资源池”，或打开[资源池](/resources/pools)，为一组资源建立独立的受管身份。启用前先选定成员类型和明确的策略。保存的规则可以指定单一成员、实时显示分组或嵌套池。搜索及分页查看成员不会改变下次接受操作时的选择。

宿主机池与单一宿主机出现在同一个“宿主机”字段中。“默认宿主机”继承所属位置的选择；“可用空间最多”明确使用原有调度器。修改模板会保留明确选择的宿主机。接受创建后，原生任务重放会保留实际宿主机；修改将来的默认值不会搬迁已有环境或提供者的卷。

资源池使用权限与实际成员的使用权限分别检查。借用成员还需要“出借成员”、成员当前的“通过资源池”许可，以及许可提供者当前的权限。存储、模板、资源和数量限制始终保留。宿主机数量限制统计通过实际权限条目创建、尚未删除的环境与提供者注册；停止的注册仍保留配额。借用不会授予一般成员使用权限或定义读取权限。隐藏的成员在池的成员列表中仍然隐藏。

“复制”会把全部已保存的规则和自身路由设置复制到新资源池，包括隐藏或尚未加载的规则。选择新名称和归属位置；副本默认仅自己可见。复制不会选择成员，也不会复制权限、“通过资源池”同意、健康状态、轮换或用量。即使后续读取失败，也不会重新创建已经确认的副本。

选择记录显示已保存的成员选择及实际策略。打开详情可分页查看原始候选成员和原因；每次读取都按当前权限保护名称和预估费用。过期详情会明确标记，查看或重新连接不会重新选择成员。

恢复已丢失的提供方运行时会保留配置的主机资源池。审阅只检查可用性，不会消耗策略轮次；已接受的原生任务才会预留一个实际主机，并在确认丢失时保留同一选择和单元。修改未来的默认值不会移动已有单元。
