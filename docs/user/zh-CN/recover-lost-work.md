# 机器丢失后恢复工作

当主机、机器或环境不会再回来时，你声明它丢失，把它的工作移到别处，并告知受影响的人。本页依次讲这些步骤，然后讲服务器、挂载和托管提供方会怎样，以及如何移除主机。

## 声明丢失

在不会再回来的主机、环境或机器的**⋯**菜单里使用**声明丢失…**。主机或环境的管理者可以这样做。个人机器的所有者可以声明那台机器丢失。

1. 阅读受影响的环境、会话、保留的数据、挂载、托管提供方和作业。私有的工作显示为数量。
2. 选择**通知**，输入确切的名称，然后确认。

Orch 会永久吊销受影响机器的身份。它不会向丢失的机器发送任何清理命令。依赖它的作业会以**已丢失**结束。结果会让你审阅过的后果保持可见，直到你关闭它。

会话保留它们的对话和环境。它们的横幅写着**已阻塞：其环境已丢失**，并提供**在别处运行…**。投递从未被确认的输入保持失败，由它的作者决定是否重试。

## 恢复环境

从丢失资源的菜单，或它的收件箱条目，打开**恢复…**。你也可以同时选择多个环境。在仍然有响应的主机上，**全部移动…**使用同样的审阅。

选择大家共用的**目标主机**，或让**自动**保持选中。每一行都可以选择另一台主机。你需要管理那个环境，并且需要对目标主机和模板有你自己的访问权限。你不管理的环境显示为数量，由它们的所有者恢复。

为每一行选择一个操作：

- **移动**复制一个仍有响应的环境。它保持同一个环境及其会话。复制的主目录让本地智能体可以恢复。当主目录无法传送时，它们通过**延续**，从记录的对话继续。
- **重新创建**再次提供丢失的环境。它的页面、所有者、设置和会话都保留。审阅会检查工作区和主目录的卷是否已恢复。否则它只复制 Orch 仍然持有的文件的内容。默认开启文件中转。需要保留的文件应创建快照；确认前请核对服务器已有文件与缺失文件的数量。**文件列表不可用**表示覆盖范围未知。
- **切换会话**把会话送到下一节所描述的目标环境。

计数在后台进行。确认会等待所需的计数和当前的审阅。未知的大小显示为 **–**。被阻止的一行不会阻止其他可以运行的行。一个进度视图显示各个独立的作业。**重试失败的**会选中失败或丢失的成员。取消会保留已经完成的工作。

管理员有意使用已有的管理操作。审阅会写出将被添加的权限，审计记录会记下这次绕过。

## 选择切换目标

**目标环境**可以指定一个已存在的环境，或为整个批次选择**一个新的共享环境**。对新环境，请选择它的名称和主机。普通的会话批次也可以保留每个会话自己的环境。已丢失、已移除或已关闭的目标会被略去。

确认之前，请审阅目标，以及被复制文件的后果。批次按名称使用那个环境，即使它的会话保留各自对提供方和模型的选择。

## 通知受影响的人

每次确认都有自己的**通知 N 人**选项。「操作通知」（`notify.operations`）决定默认值：初始为始终关闭，也可按需选择阻塞工作时开启或始终开启。确认前可以更改选项。该设置遵循所属位置和系统锁定。跨多个位置恢复时采用系统默认值。

- 这个数字统计将根据他们自己的通知设置收到这类通知的人。悬停、聚焦或按下这个数字，可以打开共同的人员列表。它显示你有权看到的名字和其余人的数量。选择一个人可以打开他的卡片。
- 一条收件箱条目为每个接收者汇总这次操作所影响的工作，更新保留在那条条目里。关闭**通知**会抑制它。
- 在**设置 → 通知 → 种类**里选择你接收的种类。更改会自动保存，保存失败会显示原因。这会改变你自己的选择。别人的**通知**选项不能打开你已经关闭的种类。

## 服务器与挂载

被导入的 MCP 服务器，在它的机器丢失或被删除之后，仍保留它的定义、设置和权限。没有另一个就绪的提供项时，它的页面会写**没有机器**。

之后的机器只有在报告了相同的名称和定义时，才会立即提供同一个导入：传输方式、命令或地址，以及环境变量的名称。值和秘密不会被比较。页面显示这个提供项及其时间。不同的定义保持**已发现**。有权从那台机器导入的服务器管理者可以选择**使用这台机器的**来记录新的定义。仅仅发现一个服务器绝不会打开它。

挂载保留它的定义和它是否开启的选择，只是没有当前位置。已丢失的位置显示**已丢失**和它们最后已知的大小，从未计算过的大小显示 **–**。把挂载附加到另一台主机之前，请先在那里添加一个位置。不会在丢失的机器上尝试任何清理。

对依赖于被声明丢失的机器的挂载，检查其内容会以**已丢失**结束。它自己不会开始任何进一步的读取。需要的位置可用之后，请选择**检查**进行新的比较。

## 托管提供方

容器已丢失的托管提供方保留它的设置和权限。它的容器里的文件不可用。它的管理者可以在容器设置里选择**重新创建**，审阅目标和**通知**选项，然后确认。只存在于旧机器上的凭据可能需要重新登录。

## 移除主机

**删除…**会一起审阅四组内容：环境、挂载的位置、MCP 服务器和托管提供方。默认情况下，环境会先被恢复。改为移除它们，则使用它们通常的数据保留期。只有你有权管理的环境才由你更改。

- **挂载的数据。** 每个挂载的数据有它自己的选择：**留在机器上**、**移动**或**删除**。默认是**留下**。**移动**使用通常的**复制**传输，进入另一台主机上的新位置，由你选择它的目标。原本就存在、交给 Orch 的目录，即使在复制之后也保持完好。**删除**会要求输入挂载的确切名称。更早保留的副本有它们自己的行。
- **已移除环境的文件**默认**等到**它们现有的日期。当前所属位置的管理员可以选择**立即清除**并输入环境的名称。其他管理者可以在日期之后清除。删除或重试本身都不会缩短这个日期。
- **清除 Orch 保留在那里的内容**默认开启。它列出 Orch 拥有的容器、镜像、构建、网络和工具版本及其大小。留下的数据，或正在等待的数据，不包括在内。无法归属的卷和层有它们自己的选择：**留下**，或你通过输入确认的**删除**。不完整的清单会阻止清除，未知的大小显示为 **–**。
- **服务器和提供方。** MCP 服务器不再在那里被提供，已导入的资源保留。托管提供方保持不可用，除非你选择在别处重新创建它们。

阅读阻碍和保留数据的任何期限，选择**通知**，输入主机的名称，然后确认。主机会暂停，作业先完成你这一部分的工作。别人的环境不会阻止开始。进度行会写出剩下的恢复、需要它们的管理者恢复或移除的环境，或保留数据的日期。在它等待时取消，会让主机保持登记，已被接受的级联继续进行。

结果列出留在机器上的对象及其大小。丢失的主机只会从 Orch 里被移除。在可以连上那台机器时，请在机器上运行 `orch-node uninstall --purge`，来审阅并移除它仍然拥有的对象。

## 默认环境丢失时

丢失或被移除的默认环境不会再收到新的会话。Orch 使用通常的后备方式来选择环境。选择了**通知**时，受影响话题的管理者会收到通知，请他们选择另一个默认值。
