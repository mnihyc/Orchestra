# 添加任意类型的提供方

## 1. 选择怎样连接模型

打开**资源 → 提供方 → 添加提供方**。
可先在顶部**从示例填入**，也可直接填写下方的自定义接口；示例填写的是同一组字段。
模型服务，包括你在 GPU 机器上运行的模型，选择 **API 地址**，填写基础地址和它使用的
接口：Messages、Responses、Chat Completions 或 Embeddings。订阅选择**程序自己的登录**及已注册的
登录程序。不可用的程序仍在列表中说明原因。**添加智能体配置**会在这里打开已有的添加流程，
并保留尚未完成的提供方。机器安装了程序并不代表它已经报告登录能力；可从机器登记该程序，
或先运行一次尚未读取能力的配置。

## 2. 选择凭据和机器

地址可使用 **API 密钥**或**无凭据**，订阅使用程序自己的登录。选择提供方所属位置，
再继续选择机器和数据源。**密钥保存在**或**登录保存在**选择凭据的保管位置；不使用凭据时，
**连接机器**选择负责连接模型的机器。本机策略必须允许该地址。`localhost` 指这台机器，
不是浏览器。**连接运行在**是另一项独立选择，两者可以使用同一台机器或新容器。
订阅的登录程序必须已在所选机器上提供。

## 密钥建议

添加 API 提供方时，可以先粘贴**密钥**。已知格式会建议已有示例和**密钥用途**，并标注
**来自密钥格式**。选择**使用**会填入示例字段，示例本身标注**来自目录**。
两种选择都可以修改。无法识别或存在多个匹配时，由你选择提供方。
建议不能证明密钥有效，也不能证明能力、价格或限额。

下一步在保存前确认用途。**模型密钥**存入提供方原有的模型密钥保管处；
**管理密钥**只交给所选信息来源声明的管理密钥字段。
来源没有该字段时，可以更换来源，或先不填写这份密钥，完成设置后再添加。
模型密钥也可以稍后在**登录与密钥**中添加。返回上一步、刷新设置或保存遭拒都保留编辑。

保存后，提供方的正常首次读取才会带回厂商信息。先在其页面查看，再启用模型。
输入或确认密钥不会请求厂商；未保存的密钥只留在表单中，直到你选择保存。

## 3. 选择谁报告模型和限额

已知厂商可使用内置读取器。自有适配器可以选择**机器上的程序**或**数据源地址**来报告
模型、限额和用量。数据源地址实现提供方数据源接口，与模型 API 地址是两个用途。
缺少程序时可在这里直接注册，也可到机器的**程序**部分注册。
[注册自己的程序](register-your-program.md)解释两种程序的区别。数据源只报告它知道的内容；
未报告余额不代表余额为零。

例如，GPU 模型填写其服务地址，选择 **Chat Completions**，再选择密钥或无凭据。
选择能连接它的机器，在那里注册用于列出模型、报告限额的数据源，并把它用于所声明的
字段。创建后启用需要的模型。整个过程不需要厂商预设。

## 4. 创建、登录并使用

选择**添加提供方**。在**登录与密钥**中添加设置时未填写的密钥，或完成提供的订阅登录。
保存密钥也会读取可用模型和事实。**刷新**会再次读取；在**模型**中接受并启用需要的模型，
读取不会自动把它们加入。
在线程中选定提供方和已启用的模型，发送一个小请求。保存配置不等于模型已可用，
一次完整的运行才证明整条路径正常。
如果提供方已添加但后续设置失败，打开提供方并检查模型，再完成设置。

地址被拒绝时，按字段旁的原因选择其他机器，或请机器的管理者允许该地址。
缺少程序时先在所选机器注册；登录过期时回到**登录与密钥**。
只向应该使用这份密钥或订阅的人分享权限。
[数据源接口文档](/help/provider-readme)说明如何编写数据源；该开发文档目前为英文。

## 本地嵌入

在普通示例列表选择 **Local embeddings**，可在提供方运行环境中运行随附的嵌入模型。
它填入协议、回环地址、模型和 256 维。运行模板是普通 Dockerfile 模板，
可以到**资源 → 模板**编辑或移除。移除后不会变成隐藏的内置对象；以后需要时会创建新的模板。

创建提供方后，要单独把它保存到搜索的嵌入设置。管理页可以在创建后打开该编辑器。
**模板 · Local embeddings**链接显示实际使用的模板。
[语义搜索](semantic-search.md#choose-embeddings)介绍费用承担、前缀和索引选择。
