# 资源与移动

环境是工作运行的地方。同一个环境里的会话共享它的工作区、主目录、进程、浏览器配置和显示桌面。从会话打开**文件**或终端，到达的是整个环境。会话的目录只是它的智能体开始的地方。不能共享这些东西的工作，请使用不同的环境。

端口、浏览器和显示桌面属于环境。会话的视图是到达它们的途径，使用会话所显示的权限。浏览器配置可以保留登录，所以同一个环境里的其他智能体可能读到它，尽管它不在工作区的文件列表里。共享显示桌面的剪贴板里的内容，可以传给每一个观看的人。

项目容纳话题和更多的项目，目录树把后者叫作文件夹。话题可以在它们之间移动。位置上的角色会涉及它的文件夹及其内容。共享一份文档或一个会话，不会共享它的文件夹。位置的共享对话框会区分位置本身和连同内容的位置。

## 删除环境

打开环境的菜单，选择**删除**。确认框先说明将会失去什么，然后才要求输入名称。

- 对由模板创建的容器，确认会立即把移除排入队列。Orch 停止并移除容器，然后在你确认时定下的保留期内，保留它拥有的卷。保留期从容器真正被移除时开始，所以离线的主机不会耗尽恢复的时间。原本就存在的目录和借来的挂载会保留。
- 你登记的目录会失去它的登记。它的文件仍留在它所在的机器上。
- 临时环境的卷没有保留期。确认之前请阅读关于它所拥有的卷的警告。[临时环境](temporary-environments.md)说明自动清理、一小时之前的通知、**保留**和导出。

## 提供方和模型

提供方通过 API 密钥或智能体程序的登录提供模型访问。它把凭据保管在自己的容器里，或保管在已连接的机器上。它的页面区分已保存的设置和已就绪的提供方，显示它可以提供的模型，并且只报告供应商真正给出的套餐窗口、点数和到期时间。未知的点数或到期时间显示为未知。

**刷新**会读取提供方及其可用模型的当前详情。新提供的模型作为建议出现，由管理者决定是否打开，已经消失的模型会被标出。每一项详情都说明它是什么时候读取的。供应商报告的每个重置时间之后一分钟，Orch 也会读取一次，所以新窗口不用点击就会显示。例如，报告的重置时间是 14:00，就会安排在 14:01 读取。失败的读取会让它的错误和时间保持可见，未知的余额或读取时间保持未知。没有单独的**测试**，**刷新**也绝不会自己打开某个模型。

模型的管理者打开可用的速度、访问方式和上下文大小。会话再在这些选项里选择。模型的某个条目所允许的最大值，与会话当前的设置是两回事。路由名称发送给提供方，显示名称展示给人看。名称改变了，或模型被关闭了，会在下一轮开始时重新检查。提供方的模型编辑器把已知的访问方式命名为 **Daybreak 蓝**、**Daybreak 红**和**标准**。其他程序名称按它们提供的名称显示。

## 智能体运行方式

智能体的设置说明它在哪里运行、谁运行它的工具，以及它的登录保存在哪里。

- **在提供方运行**让智能体留在提供方，由 Orch 在环境里运行它的工具。
- **转发模型请求**让智能体在环境里运行，并通过 Orch 发送它的模型请求。
- **复制登录信息**借出一个被允许的令牌的副本。
- **移交登录**把整个登录借给一个位置，直到归还。
- **使用本地登录**使用环境里已经有的登录。

提供哪些选项，取决于提供方所有者的同意、策略、智能体程序声明它能做什么，以及机器或主机当前的事实。

提供方拥有自己的登录及其续期。托管的提供方在空闲停止和重新创建期间保留它的主目录，需要续期时会被启动。导入的凭据会复制到这里。刷新过的外部令牌，可以由它的管理者再次导入，或用提供方的导入命令导入。如果登录的副本在别处也被续期，请按该登录方式关于只保留一个续期副本的指引处理。被移交的登录归还失败时，环境无法停止，直到它的管理者处理好，或声明它已丢失。

## 配置、主机和计算机

智能体配置设定一个智能体：它的版本、选项、变量和它支持的方式。它声明的字段给出表单、选项和帮助。配置不拥有另一个容器。**配置信任**控制是否可以加载项目设置、钩子、插件或服务器。指令文件本身不会给出这种信任。

- **配置**列出已保存的**配置键**，不显示它们的值。**显示全部**会展开较长的列表，嵌套的名称与名称中带点的键保持区分。
- JSON 编辑器保留程序没有以普通控件显示的选项。声明的模型参数在准备一轮时，仍然服从提供方已打开的选项和程序的限制，程序自己的登录也一样。配置不能绕过它们。
- 配置的技术详情根据声明写出执行器和工具集的名称。打开它们会读取配置尚未给出的执行器名称。失败的读取有**重试**，没有报告的名称保持不可用。很长的安排列表和工具集列表一次显示一页。

主机根据模板创建托管环境，选择器会显示什么是空闲的以及模板需要什么。已连接的机器提供它的所有者设置的角色和文件夹。它一开始是所有者的资源，并且可以被共享。它的本地策略在机器上更改，服务器的管理员不能放宽它。当提供这项操作时，**重新登记**会续上它的登记并保留它已登记的身份。直接在机器上运行的环境在 Linux 上可用，其他平台上未经测试的能力不会被提供。

在机器的**策略**标签页上，执行器的选项来自它报告的执行器和工具集，带有它们的名称和说明。打开编辑器会读取机器的选项，读取失败时可以重试。已保存但不再被报告的选项可以保留或清除。较早保存的别名仍按它们所声明选项的名称保持选中。保存只会更改机器所有者已经交出的键。

## 按角色登记

连接机器，包括它的角色、账号和运行方式，见[连接一台机器](connect-a-machine.md)。角色简述如下：

- **环境**：让人们在这台机器的文件夹里工作。它的环境设置约束这些文件夹里的文件写入、终端、浏览器、显示桌面、工具，以及端口向谁开放。
- **智能体**：在这里运行智能体，带有它自己用于智能体程序和获取构建的设置。
- **提供方**：把提供方的密钥保管在这里。它的登录、上游和安排设置，与环境和智能体的设置各自独立。
- **节点**：让 Orch 在这里创建环境。节点是单独的程序 `orch-node`，运行在 Linux 主机上。要在同一台电脑上同时有连接器和节点，请把它既添加为主机又添加为机器。节点把环境设置保留为它的容器的上限：它的驱动、存储、钩子和资源设置约束模板可以请求什么。

机器的所属位置默认是你自己的组织，你也可以选择你有权创建机器的另一个组织。登记令牌保留这个所属位置，机器一开始只属于你私有：同在一个组织并不会让其他成员获得访问权。

对于你选择的每个角色，**将其设置交给 Orch**一开始是关闭的。打开它就把该角色的策略交给 Orch，本机保存的值仍然优先。另一个单独的**专用**开关声明这是一台只做这件事的虚拟机或电脑。这是本机的同意，Orch 之后无法替你打开它。命令会随每个选择而变化，所以请使用显示出来的完整命令：它的令牌只能使用一次，并与这些选择绑定。

以后要更改角色，机器页面会给出命令 `orch-connector roles set environment,agent,provider`。编辑列表，在那台电脑上运行它，并重启连接器。它重新连接时会报告所选的角色。页面没有远程编辑角色的操作。要添加**节点**，请把主机单独登记。

## 环境和访问入口

环境的管理者控制把会话放进去、更改它的目录或限制，以及把它移除。管理一个会话并不给予这些。一个环境可以同时打开多个会话的视图，对于通向共享环境的每条途径，都会检查会话的权限。当驱动和运行时都已知时，环境的页面会把它们一起写出来。

**端口访问**按所提供的方案，通过 HTTP、原始 TCP 或 UDP 发布一个正在监听的程序。端点及其受众属于环境。打开端口之前，请阅读告知调用者和接收者的内容、到期时间，以及关于向外共享的选择。链接是另一种进入的方式，页面显示它的种类和它的接收者。永远不要假定一个已发布的端口私下属于打开它的那个会话。

浏览器使用保留的配置，加入同一个配置就会共享它的标签页和登录。观看和控制是各自独立的权限。显示桌面也可以把剪贴板数据传给观看的人。视图显示当前的能力和限制，包括是否有浏览器沙箱可用。关闭 Orch 拥有的浏览器或显示桌面，会结束它的进程。已经存在、只是被宣布的那一个有自己的生命周期。

## 挂载和工具服务器

挂载以所示的模式附加数据。共享挂载把写入送到源，只读挂载不允许写入，私有视图把这个环境的更改与源分开保存。分叉或移动方案会显示挂载的位置和模式，被分离的挂载会说明它为什么不能跟随。私有工作区不是通过在共享环境里选择一个子目录得到的。

MCP 预设在打开它们的环境里运行。在电脑上的智能体程序自己的配置里找到的服务器，是被有意导入的，它的定义和秘密留在那台电脑上。请在应该使用它的环境里打开导入的服务器。智能体程序会报告它是否能把会话限制在所给的服务器上。无法提供的严格边界是可见的。

列表里的每个服务器都有当前的状态。某个服务器失败时，请阅读它的退出情况和最后的输出（已遮蔽），然后用**重启**，并使用环境管理权限，只启动那个服务器。对于整个环境，**重启…**先写出将会停止什么，并把每个文件保留在同一个容器里。两者都显示作业的进度和真实的结果。[示例和等待的规则](change-a-running-environment.md#restart-one-tool-server)说明什么时候选择哪一个。

## 模板和更新

模板通过一个取决于驱动的表单提出运行时。有些驱动可以导入镜像、Dockerfile 或归档。导入只是提出表单，不会创建运行时。限制、资源限额、网络限制、挂载和私有视图，取决于驱动已验证的能力。不被支持的受限网络会拒绝这个方案；它绝不会以开放状态启动。

**更新**或**重建**作用于你管理其页面的环境或托管提供方。请阅读方案及其对运行中会话的影响。进度跟随被保留的作业。旧的一侧只有在新的一侧于提交点被检查之后才会退役。在那个点之前取消，仍由源负责，当某个阶段无法撤销时，作业会说明如何恢复。

## 分叉和移动方案

**创建分叉**会创建新的会话，**切换**则保留当前的会话。方案写明保留多少历史、目的地的选择、选择的文件、主目录和挂载的复制，包括某个条目为什么被分离。历史选**无**，意味着源的全部对话被有意丢弃。对正在使用的大目录树，请精确选择要复制的文件，并阅读它们估计的字节数和时间。Git 的状态只在你要求时才刷新。

复制主目录或私有层的请求，需要它经过审阅的传输方式。如果这种方式不可用，方案会阻止复制。它绝不会悄悄把这些更改留下，也绝不会改去复制挂载下面的数据。

每个资源都有所有者和所属位置，与包含它的位置一起显示。它在它的权限页给予访问权限的地方被使用，不只是在它创建的地方。删除或移动它需要**管理**，不会借用恰好使用它的某个会话里另一个人的权限。给予访问权限之前请阅读[共享](workflows.md#share-a-thing-or-a-place)，关于它的工作的限额见[设置与消耗](settings-and-usage.md#limits)。

你能阅读的资源会让管理它的操作保持可见。没有**管理**时，操作保持禁用，并写明这个要求。打开或复制它的链接仍然可用。取决于状态的操作，以及删除之前的审阅，保持它们通常的检查。

## 资源池

资源池是可以作为一个模型、提供方、环境或主机来选择的已配置资源组。可从现有分组创建资源池并选择规则。禁用的草稿仍可查看和编辑。启用与借出成员分别由用户明确选择。

仅有资源池使用权限不会获得成员使用权限。借出成员还需要成员的“通过资源池”同意，以及同意者当前的共享权限。模型、服务、推理强度、运行方式和位置必须由一条完整授权覆盖。继承中的私有设置和锁定同样适用于借出。除非成员侧条目允许显示名称，否则隐藏成员仍保持隐藏。

实际选择处会显示成员、规则和跳过原因。资源池不会自动移动线程的环境，也不会另建重试机制。失败后的行为由调用恢复决定；已接纳但结果不确定的请求保留原成员和回执。
