# Codex 历史与转接

[English](../codex-history.md)

Codex 将历史保存在自己的主目录中。需要保留原生会话时，应将该主目录连同环境的卷一起保留。
Orch 不会将某个 rollout 文件移植到另一个主目录，也不会强制 Codex 使用旧的历史存储格式。

| 目标位置 | 历史传递方式 |
| --- | --- |
| 同一个主目录 | 续接现有的原生会话 |
| 环境以“原样挂载”或“复制”连同主目录一起迁移 | 下次使用该线程时重新打开原生会话 |
| 另一个主目录、另一个凭据的主目录，或没有原卷的机器 | 在目标模型窗口允许的范围内携带最近的已记录轮次，并提供完整对话文件 |

连同主目录迁移时，迁移的是卷，不会在迁移过程中打开每一个线程。线程在下次使用时才打开。

## 原生分支的核对

在某一轮次处创建原生分支之前，还必须用程序记录的完整对话核对该轮次的位置。
**原生分支检查大小**默认为 32 MiB，程序记录本身也有 32 MiB 的限制。
调大设置不会取消记录大小的限制，也不会取消对内容和顺序的核对。

无法完成原生核对时，计划会明确写出**中立导入**或**文件交接**。
确认前应先查看传递方式。一个会话可以原生续接，并不表示该历史已经通过原生分支的核对。

## 进入另一个主目录

Codex 不提供可将原始模型历史无损导出到另一个主目录的接口，因此这里使用 Orch 已记录的对话。
携带内容是最近的、能放进所在位置“延续份额”的轮次；该份额默认是新模型窗口的 80%。
完整对话会逐页写入工作区中的文件。模型输入受窗口大小限制，完整对话文件的磁盘工作量则随对话长度增长。
应为该文件预留磁盘空间。

原生续接或接管会话后，时间线中的一条普通历史行会说明：该会话保留原有的常驻指令，
指令更改在下一个新会话中生效。这条说明不表示本轮失败。

传递方式的选择见[将线程历史带给另一个智能体](../../user/zh-CN/carry-a-thread.md)。
版本验证与保留规则另见英文的[智能体版本检查](../harness-build-checks.md)和
[托管智能体历史](../agent-history.md)。
