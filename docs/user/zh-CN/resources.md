# 资源与移动

环境是工作的运行位置。同一环境里的线程共享工作区、主目录、进程、浏览器配置和显示。
从线程打开文件或终端可到达整个环境，线程目录只是代理起点。需要不同信任边界时应分环境。

端口、浏览器和显示属于环境，线程视图只是按权限打开它们的入口。浏览器配置保留登录，
同环境的其他代理可能读取，即使它不在工作区文件列表中。共享显示的剪贴板也可能给观察者。

项目可包含话题和子项目，子项目在树中叫文件夹，话题可在其间移动。位置角色沿后代生效；
共享一份文档或线程不共享文件夹。共享时区分位置本身与位置连同内容。

## 删除环境

菜单选择删除，确认先说明后果，再要求名称。模板创建的单元接受后立即排队移除，
Orch 停止并删除单元，再按确认时冻结的保留窗口保存自有卷。窗口从实际移除时开始，
离线主机不会消耗恢复时间。现有目录和借用挂载保留。

注册目录只失去注册，机器文件保留。临时单元没有普通卷保留窗口，确认前读自有卷警告。
[临时环境](temporary-environments.md)说明清理、一小时通知、保留和导出。

## 提供方和模型

提供方通过 API 密钥或代理程序登录供给模型，凭据保留在提供方运行时或连接机器上。
页面区分已存设置和实际就绪，只显示供应商确实报告的窗口、额度和到期，未知保持未知。

刷新读取当前信息和可用模型。新模型只是供管理者启用的建议，消失的报价会标记。
每项带读取时间，供应商报告重置后一分钟也会读取，如 14:00 重置后 14:01 读取。
失败保留错误和时间，未知余额或时间不推测。没有独立测试动作，刷新不启用模型。

模型管理者开放速度、访问计划和上下文，线程再选自己的值，允许最大值不同于当前设置。
路由名发给供应商，显示名给人看。改名或停用后，下一轮会重新检查。

## 代理运行方式

设置说明代理程序在哪里、谁运行工具及登录保存在哪里。与提供方运行把程序留在提供方，
工具在环境执行；转发模型调用把程序放在环境，模型请求经 Orch；复制登录访问借用允许
的令牌副本；移动登录独占借出完整登录直到归还；使用本地登录使用环境已有登录。
选择受所有者同意、策略、适配器声明及当前机器事实约束。

提供方的模型编辑器将已知访问计划显示为 **Daybreak 蓝**、**Daybreak 红**和**标准**；
其他计划按提供的名称显示。

提供方拥有登录和续期。受管运行时空闲停止和重建后保留主目录，需要续期会启动。
导入会复制凭据，外部刷新后管理者可再次导入。两份登录都可能续期时，遵循该方法对
唯一续期副本的说明。独占归还失败时环境不能停止，需管理者解决或明确声明丢失。

## 配置、主机和计算机

代理配置包含程序版本、选项、变量和支持方式，表单来自它的声明，不拥有另一个运行时。
配置信任决定是否读项目设置、钩子、插件和服务器，指令文件不自动授予这种信任。

配置的技术详情使用声明中的执行器和工具集名称。打开详情时，会读取配置尚未提供的
执行器名称。读取失败后可以重试；未报告的名称保持不可用。较长的运行方式和工具集
列表逐页显示。

主机从模板创建受管运行时，选择器显示空闲量和要求。连接计算机提供主人配置的角色和
允许根，初始属于主人，可以共享。本机策略只能在机器修改，服务器管理员不能扩大。
重新注册在可用时保留身份并更新注册。目前原生环境操作声明支持 Linux，未验证平台能力不提供。

计算机的策略页从机器报告的执行器和工具集提供选项，名称和说明来自这些声明。
打开编辑器时读取选项，读取失败可重试。不再报告的已保存选项可保留或清除；
旧别名在声明的选项名下保持选中。只能保存主人已交出的策略键。

## 按角色注册

添加机器中可组合环境、代理、提供方；节点单独注册，使用不同程序。连接器选用户服务
或前台，已有连接器时给另一个实例命名。节点的后台方式是系统服务。显示命令后，
在该机器运行完整命令；安装前检查程序与系统发布是否匹配。

所属位置默认自己的组织，也可选有创建机器权的组织。一次性令牌保留该选择，机器初始
只给你，同组织不自动获得访问。改所属位置会生成新命令，必须用当前显示的命令。

### 环境角色

环境允许人在本机目录中工作，环境设置限制这些目录中的写入、终端、浏览器、显示、
工具和端口接收范围。

### 代理角色

代理在此运行程序，有自己的代理程序和构建下载设置。

### 提供方角色

提供方在此保管模型密钥，登录、上游和运行方式与环境、代理设置独立。

每个连接器角色的把设置交给 Orch 初始关闭，开启只交出该角色策略，本地保留值仍优先。
独立的专用声明机器没有其他用途，是本地同意，不能由 Orch 日后打开。

命令随选择改变。Linux 和 macOS 可有 `--roles environment,agent --delegate environment,agent --dedicated`，
Windows 用 `-Roles`、`-Delegate`、`-Dedicated`。`--delegate-policy` 或 `-DelegatePolicy`
交出全部策略。令牌绑定这些选择，可信注册后才保存角色及其设置。旧令牌保持原默认行为。

### 连接器运行位置

连接器以你的账号运行，不用 sudo 或管理员权，在注册目录工作，不依赖终端当前目录。
Linux 程序在 `~/.local/bin/orch-connector`，数据在 `~/.local/share/orch-connector`
或 XDG_DATA_HOME。macOS 数据在 `~/Library/Application Support/Orch/connector`。
Windows 程序在 `%LOCALAPPDATA%\Orch\orch-connector.exe`，数据在其 connector 目录。

用户服务在 Linux 是 systemd 用户单元，macOS 是 launchd 代理，Windows 是登录任务。
Linux 默认注销即停，除非运维开启驻留；后两者在登录期间运行。用 `orch-connector service stop`
或 `service start`，Windows 先调用 `& "$env:LOCALAPPDATA\Orch\orch-connector.exe"`。
前台增加 `--no-service` 或 `-NoService`，对话框完整命令会安装并启动；直接运行安装器时，
随后执行它打印的以 run 结尾命令，Ctrl+C 停止。先停已有服务，前台选择不删除服务。

另一个命名实例使用独立数据目录、身份和服务。手工命令用 `--data-dir <绝对路径>`，
Windows 安装器用 `-DataDir`，后续子命令也在前面加同一目录。默认安装省略该项。
程序文件共享，其他实例重启后使用更新。节点可与连接器并存，不能用此方式复制多个。

### 节点角色

节点让 Orch 创建环境，运行 `orch-node`。同机两用应分别添加主机和机器，在 Linux
主机运行所属组织的节点命令。交接策略增加安装器 `--delegate-policy`，连接器拒绝节点角色。
节点自己的环境设置限制单元，驱动、存储、钩子和资源策略约束模板。

节点以 root 运行，程序 `/usr/local/bin/orch-node`，配置 `/etc/orch/orch.toml`，数据
`/var/lib/orch-node`。系统服务是 `orch-node.service`，用 systemctl stop/start 管理。
前台加 `--no-service`，安装后以 root 运行 `/usr/local/bin/orch-node --config /etc/orch/orch.toml run`，
Ctrl+C 停止；对话框完整命令已含启动。先停现有服务。每机器一个节点，通过访问共享主机
服务多个组织，不要装第二个。

### 移除连接器或节点

先在 Orch 撤销机器，再运行 `orch-connector service uninstall`，命名实例用原 data-dir。
只停止移除服务，保留数据和身份。删数据前检查，保留其他实例、嵌套 instances 及工作目录。
最后一个实例移除后才移除共享程序。

节点先移除环境、卷和主机，再以 root 停止禁用服务、移除服务文件并重载 systemd。
检查后移除本节点程序和数据；其他 Orch 程序使用的配置保留。前台没有服务可移除。
只移除服务不撤销注册，也不删除工作。

### 本地改变角色

机器页显示 `orch-connector roles set environment,agent,provider`，修改列表后在本机运行并重启。
认证重连报告选择的角色，网页不远程改角色。增加节点要单独注册主机，roles set node 会说明程序。

## 环境和访问入口

环境管理者控制线程放置、目录、隔离和移除，管理线程不授予此权。同环境可有多个视图，
每条访问路径都检查线程和环境权限。
已知驱动和运行时名称时，环境页面会将两者一起显示。

端口按方案以 HTTP、TCP 或 UDP 发布监听程序。端点和接收范围属于环境。开放前读接收者、
期限和外部共享披露。链接是另一入口，页面显示类型和收件人，不要认为开放端口属于单线程。

浏览器配置共享标签页和登录，观察与控制权独立。显示剪贴板可能给观察者。视图显示当前
能力和限制，包括浏览器沙箱可用性。关闭自有浏览器或显示会结束所属进程，通告已有进程
有自身生命周期。

## 挂载和工具服务器

共享写入到来源，只读不准写，私有视图把本环境修改与来源分开。分支或移动方案显示位置
和模式，无法跟随的分离项会说明原因。在共享环境选子目录不创建私有工作区。

MCP 预设在启用它的环境运行。从代理本机配置发现的服务器需明确导入，定义和秘密留在
本机，再为环境启用。适配器报告能否将会话限制为给定服务器，不支持严格边界会显示。

每个服务器有当前状态。失败先读退出及遮蔽后的末尾输出，再以环境管理权只重启该服务器。
整个环境的重启先说明哪些会停，同一单元文件全保留。两者都显示作业进度和实际结果。
[示例和等待规则](change-a-running-environment.md#restart-one-tool-server)说明如何选择。

## 模板和更新

模板通过驱动表单提出运行时。部分驱动能导入镜像、Dockerfile 或归档，导入只填表，
不创建运行时。隔离、资源、网络限制、挂载和私有视图依赖已验证能力。不支持受限网络会
拒绝方案，不会开放启动。

更新或重建作用于有管理权的环境或提供方运行时。检查对运行线程的影响，跟随持久作业。
新侧检查成功并到提交点后才退役旧侧；此前取消保留来源为准，不可逆阶段会说明恢复。

## 分支和移动方案

分支新建线程，切换保留原线程。方案列出历史保真、目标、文件选择、主目录复制和挂载，
说明为何分离。无历史明确不带任何来源对话。活动大树要明确选择文件并读字节和时间，
Git 状态仅在要求时刷新。

主目录和私有层复制必须有已审查的传输路径；不可用时阻止，不漏掉修改，也不误复制底层数据。
资源有显示所属位置的所有者和归属，使用范围由权限页决定，不只看创建处。删除或移动需
管理权，不能借用恰好使用它的线程中另一个人的权限。共享见[协作](workflows.md#share-a-thing-or-a-place)，
用量限制见[限额](settings-and-usage.md#limits)。
