# 切换代理程序并延续历史

## 打开方案

切换改变当前线程的提供方或代理配置。分支创建另一个线程；分支到可打开方案，
选择不同目标或历史。选择可用的提供方、配置、模型和环境，再阅读当前条件。
不可用的选项会指出缺什么。

普通目录也是正常工作区，Git 可选。需要 Git 的动作会在选择处说明需要仓库；
普通轮次不要求先准备仓库。

方案会显示目标审批模式。程序支持当前位置的模式时会保留；否则使用程序提供的
第一个普通模式，例如“询问”。锁定或不允许的模式会阻止方案，并说明原因。

## 选择历史

**延续**优先使用目标原生支持的方式：同一会话、原生分支、移植或导入。
无法原生导入时，会把最近轮次逐字写入交接内容。在历史控件中可选择全部、
截至某轮或一段范围。

位置的携带比例为新模型保留工作空间，默认占窗口的 80%。方案显示携带量、保真度，
以及警告和舍弃内容。携带历史不依赖付费模型调用。

**摘要**在位置已配置摘要程序且成功时使用它，否则简略带入最近三轮。
延续和摘要都会把完整记录及轮次索引放入 `.orch/handoff/`，供代理继续阅读。
**不带历史**不向新会话提供来源对话，应明确选择。`thread.switch_history` 提供位置默认值，
并可以锁定。

## 检查文件和影响

历史与文件分别选择。检查目录、工作区、主目录、私有变更、挂载和 MCP 服务器。
要求的传输无法执行时，方案会阻止并说明原因。选择挂载处理方式前，阅读
[选择和检查挂载副本](check-mount-copies.md)；执行中可看[进度](follow-live-work.md#read-progress)。

确认哪些运行工作会等待或停止、所需权限以及旧数据保留。交接通知可在工作详情中阅读。
以后切换回来仍是另一次切换，不会自动只恢复上次切换之后的轮次。
