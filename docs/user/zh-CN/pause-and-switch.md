# 暂停、切换和删除

## 关闭

关闭会暂停提供方、智能体配置、模型或环境。正在运行的轮次会通过通常的中断方式停止。每个会话会记录关闭了什么，以及由谁关闭。已经发生的用量仍保留。

等待消息保留原有顺序和作者，并继续绑定该资源。关闭不会像手动停止那样挂起队列。提供方或环境的容器会在轮次停止后停止，保留卷和登录信息。

相关的已受理摘要和嵌入请求也会停止。重新启用资源也不会让已停止的请求延迟开始。

提供方、智能体配置和模型对话框接受一行可选备注，显示在等待会话和停止记录中。

提供方和模型对话框还可选择“通知相关人员”，初始选项来自“操作通知”设置，确认者可修改。模型的受影响者是使用该模型的讨论串所有者和提供方管理者；每人至多收到一条收件箱通知，停止完成时更新同一条记录。

打开数量可查看受影响的讨论串。无权查看的名称仅显示数量。

编辑挂载会更新其可用状态。选择“查看使用情况”可检查依赖它的环境。

## 启用

启用会让资源重新可用。「运行等待消息」默认不勾选。保持不勾选时，这些消息会挂起，由相关人员恢复队列或切换资源。

勾选后，符合条件的等待消息会按原有顺序运行。每条消息保留作者，并通过通常的使用权限检查。被人手动停止的队列仍保持挂起。

勾选后还会继续由关闭操作停止的最新轮次。已开始的轮次会在后续排队消息之前，以原作者身份加入可见的 Continue；尚未开始的轮次则运行原输入。若原作者已无权运行，任务会保持停止，历史记录会说明原因。启用资源的人不会成为任务作者。

数量显示消息数、会话数和开始等待的时间。悬停、聚焦或点击数量，可查看有权查看的会话名称。列表末尾会显示其余会话的数量。

批量启用使用同一个确认页和同一个等待消息选项。每行显示该资源上的等待工作。失败的行会保留结果，重试会跳过已经启用的资源。

## 切换

切换会话是独立操作。在提供方、智能体配置或模型的页面或菜单中选择它，会打开通常的批量切换。它选择当前绑定中操作者有权切换的会话，其余会话计为跳过。

源资源关闭后，仍可切换离开。目标提供方、模型、智能体配置或环境必须启用。消息保留队列位置，开始执行时会重新检查作者使用新模型的权限。

## 删除

删除提供方或智能体配置会停止其轮次，保留历史和用量。会话可以继续保留绑定，等待切换。服务器保存的密钥会被擦除，并请求在机器上退出登录。机器无法退出登录时，仍需在那里完成清理。粘贴的厂商凭据可能仍需在厂商处撤销。

提供方对话框会统计受影响的工作，并要求输入名称。先切换会话会打开独立的切换操作。删除不会替会话选择去向。

删除模型会结束该模型的成员关系，保留其讨论串、历史和用量。模型对话框同样提供明确的“通知”选项，面向该模型的受影响者。

保留的文件和其他遗留内容请使用[存储清理](storage-cleanup.md)。
