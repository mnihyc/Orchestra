# 代理程序版本

打开**管理 → 代理程序**，选择一个程序，查看其构建版本、能力和版本策略。
版本策略、当前目标、检查状态和使用情况集中显示。
点击使用数量，查看持有该版本的环境和提供方运行时。

随附版本为 Codex 0.165.0 和 Claude Code 2.1.312。
Claude Code 的绕过模式也允许危险删除操作，不再询问。详见[审批如何工作](how-approvals-work.md)。

## 兼容性检查

Orch 在后台检查构建版本。首先检查适配器所用的接口，然后在隔离单元中，
用脚本模型运行该程序的测试。测试不使用外部网络或模型凭据。
不可变的构建版本只检查一次，启动线程时不会检查。
点击**检查**可以重新检查。

点击状态，可查看缺失的接口、原生测试和已关闭的功能。
测试名称说明验证的行为，例如“运行命令前请求批准”。
已关闭的功能先说明此版本的影响和替代方式，检查器的诊断显示在下面。

| 状态 | 含义 |
| --- | --- |
| 正在检查接口… | 读取程序接口 |
| 正在检查兼容性… | 运行原生测试 |
| 已检查 | 检查通过，或随当前发行版完成认证 |
| 未测试 | 尚无完整检查；结果说明缺少什么 |
| 失败 | 检查失败；先显示关闭的功能，结果中列出对应测试 |

某项可选功能检查失败，只会关闭此版本的对应功能，其他功能仍可使用。
更新计划会警告目标版本未经测试或检查失败，管理员仍可选择它。
校验和不匹配时会拒绝下载。
Codex 0.165.0 的精确输入检查点暂不可用，因为原生目标状态和历史项目检查尚未验证。

原生导入由构建检查按程序分别决定。会导出历史的程序：导出一段简短会话，再导入到新的程序主目录。
Codex 把线程历史保存在自己的存储里，所以它的检查是：在创建对话的主目录里从某个轮次分支，
再在该主目录的副本中重新打开。若某个构建未通过，切换时的“延续”会标明程序和版本，并显示原生导入不可用。
可用时，历史改用中立格式逐项导入；不可用或容纳不下时，近期历史写入交接说明，
完整对话作为文件保留。仍可延续历史。
代理配置的覆盖值不能重新启用构建检查已禁用的原生导入。

Codex 线程在创建它的主目录里，以及随环境一起迁移的主目录里，都以原生方式续接和分支。
进入另一个主目录时，**延续**会带入放得进所在位置“延续份额”（新模型窗口的一部分）的最近轮次，
并把完整对话作为文件一并带上。

续接 Codex 会话时会保留其原有的常驻指令。修改后的指令从下一个新会话开始生效。
这是续接的正常行为，不会使轮次失败。

## 选择策略

| 选项 | 所选版本 |
| --- | --- |
| 随附版本 | 发行版的默认构建版本 |
| 最新已检查版本 | 检查通过的最新版本；没有时使用随附默认版本 |
| 最新版本（未测试） | 最新发布版本，同时显示实际检查状态 |
| 指定版本 | 你指定的确切版本 |

指定版本会列出已知版本。也可输入另一个版本，点击**获取并检查**，
读取该发行版声明的来源，跟踪工具缓存校验和后台检查。
没有可用的检查主机时会保持“未测试”，并说明原因。
检查结束后点击**使用此版本**，保存指定版本。只选择“指定版本”会保留草稿，
直到点击“使用此版本”。版本不可用时会说明原因，不会改用其他版本。

## 固定版本与继承

系统提供默认策略。组织可覆盖，项目或文件夹可进一步覆盖，环境可在自身
**设置**中覆盖。上级锁定后，下级不能覆盖。每种程序单独继承。

智能体配置指定的确切版本优先。线程不会在不匹配的版本上启动。
环境持有另一个版本时，请更新环境或选择匹配的配置。
同一单元的一份程序安装无法同时满足互相冲突的固定版本。

为某种程序选择**继承**，可以移除它的本地固定版本，保留其他程序的选项。
**随附版本**则是明确选择默认构建，可能与上级策略不同。

个人计算机继续使用所有者安装的程序。Orch 显示其报告的版本，
由所有者在该计算机上升级或降级。

环境会显示每个已报告程序的名称，即使其构建尚无目录检查。检查未知时显示“检查不可用”；尚未声明名称的程序显示“未报告程序名称”。

## 升级和降级

修改策略不会改变正在运行的单元。**有可用更新**表示单元持有的版本
与现在新建时会获得的版本不同。变更会列出前后版本，并标明**较新版本**或**较旧版本**。

更新一个环境：先在其设置中指定所需版本，再点击**更新…**。
确认前查看目标检查状态、保留的内容、停止的内容和受影响的线程。

更新多个环境或提供方：选中它们，再点击**更新…**。
主机的**运行时**页签可一起更新其单元。
管理页中的**更新 N 个环境…**会选择落后于各自有效策略的单元。
计划列出跳过的单元及原因。每个接受的单元有独立任务和回滚。

主机或程序同时涉及两类单元时，可在**更新范围**中选择环境或提供方运行时，
分别查看和确认各自的批次。点击**隐藏**后，已确认的批次仍会继续。
选择另一类单元时，会重新生成计划，显示当前正在运行的回合。

## 正在运行的回合

计划提供**等待**和以分钟计的等待时长，或**立即中断**。
立即中断就是强制更新。计划显示受影响的运行回合数量。
批量计划的同一选项适用于所有成员，初始值来自现有的变更设置。

**通知 N 人**会为此批次的每位受影响人员发送一条收件箱通知。
点击人数可查看人员列表。通知会显示更新发起者、受影响的线程数量，
并打开受影响的工作。

更新保留环境的持久文件和对话。计划列出会结束的进程和可写层变更。
“如果失败”一行说明如何恢复原单元。
确认后可查看任务进度；隐藏对话框不会停止任务。

## 镜像和离线版本

无法连接厂商时，可设置**发行版镜像**。镜像地址下按厂商主机名和路径
提供相同文件。指定版本也使用同一镜像。
只有请求较新版本的策略才会定时读取发行渠道；检查间隔为零时关闭定时读取。

管理员也可把构建文件复制到内部文件服务器，再在程序管理页中填写其 URL 和 SHA-256。
现有的构建注册接口接受同样的信息。随后运行**检查**。
节点需要预加载的隔离检查镜像，才能完成原生检查。

## 内置程序

### Codex

接口检查读取其适配器使用的 app-server 架构。

### Claude Code

接口检查读取其适配器使用的命令行参数。

### DeepSeek Harness

它使用 Agent Client Protocol。检查还会验证 Orch 提供的配套功能；某项扩展不可用时，
该版本的其他能力仍然显示。

导出 Claude Code 的原生历史前，请先暂停线程。Orch 以流式方式传输大型归档；若复制期间源文件发生变化，则拒绝导出。
