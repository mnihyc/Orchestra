# 阅读和刷新摘要

线程、话题、文档和聊天旁可显示一小段摘要。状态、可查看的摘要器及上次成功更新时间显示在一起。
描述仍是他人主动撰写的文字，摘要不会改写它。

## 阅读状态

**最新**表示与所选来源一致。来源变化后，**待更新**保留先前段落。
**更新中**表示请求正在排队或执行，原有可读摘要会保留。
**更新失败**保留上次成功的摘要并显示问题。**暂无摘要**表示尚未生成段落。
**未设置摘要器**表示没有选中可用的生成器，但已有的可读摘要仍可保留。

打开**摘要详情**（聊天中为**补看详情**），查看所选模型已声明的基础费率。缺少的费率保持为未提供。
这些是报价；实际调用消耗请查看用量页面。打开**参数**时，会话摘要仍只在消息区顶部显示一次。

查看历史消息版本时，参数会说明实时摘要不反映该版本；这里不读取或刷新当前摘要。

## 刷新与默认值

**刷新摘要**由你主动请求一次更新。打开页面或搜索不会请求付费摘要。
个人刷新归属于你，仍须满足提供方的使用权限、允许的模型及适用用量限额。
设置用途为**摘要**、对象为**成员**、按**每人**拆分的每周限额，可分别限制每个人的摘要用量。

在位置设置中选择**摘要器**并编辑**摘要目标**。线程、话题、文档、聊天和聊天标题分别设置自动刷新、
触发事件、间隔及输入输出默认值。自动刷新默认关闭。自动摘要使用摘要器设置写入者的权限，计入共享限额。
大小和间隔是默认值，不是消费限额；上级锁仍然适用。失败后的恢复遵循摘要用途的调用规则。

为单个文档设置时，打开**操作 → 摘要选项**。保存此文档的选择，或用**使用位置默认值**恢复继承。
保存选项控制之后的事件，本身不请求摘要。通过 API 发起个人刷新时，可以为这次请求选择允许的模型，
而不更改自动摘要的默认模型。

选择摘要器时，在位置设置中点按**摘要器**的铅笔，选择**一个模型**，再选择你可以使用的提供方及其已启用的模型。
**回答词元数**和**上下文词元数**在你设置自己的数值之前显示内置数值；**请求选项**和**各字段的指令**只在需要时展开。
提供方或模型无法使用时，系统会在该字段旁说明。**此处不设置**会撤销本位置的选择，改用上级位置的选择；
**以 JSON 编辑**显示原始值。

**摘要对象**的每一行都有**自动**开关。开启后，**触发时机**、**最多每隔**、**读取至多**和**写入至多**在你设置自己的数值之前显示默认值。
**保存**一次写入整个值，**放弃**恢复已保存的值；按其他开关或筛选既不会保存它，也不会把它从页面上移走。

未明确设置间隔时，线程为 120 秒，话题为 900 秒，文档为 300 秒，聊天和聊天标题为 300 秒。
话题汇总许多线程的变化；文档编辑和聊天消息通常成批出现。明确设置的共享触发间隔覆盖这些默认值，
每种目标的间隔再覆盖共享值。摘要选项显示实际生效的间隔，不会因此把默认值写成文档自己的设置。

刷新回执丢失时，再点**刷新摘要**会继续同一次请求。已确认回执后，读取失败旁的**重试**只重新读取摘要；
之后主动刷新才是一次新的请求。

首次调用模型前来源变化时，Orch 会免费重新读取来源并重建提示词。**摘要重新读取次数**默认允许三次重复，
零表示不重复。内容持续变化时会明确说明。调用模型期间来源变化时，回答不会作为最新摘要发布，也不会自动
再次调用模型。摘要框会保留原有段落并标记为待更新，说明来源变化，并提供**重新生成摘要**操作。

个人主动刷新无需先配置自动摘要器。系统按你当前的供给者权限、模型允许列表和摘要用量上限选择可用的 API 模型，
不会因此启用自动任务。没有可用模型时，摘要框会说明原因。

**已安排**显示实际的最短间隔或恢复等待原因及到期时间，原摘要仍可阅读，主动刷新仍需明确点击。
免费读取等待实际到期时间；已可运行或正在运行的任务按**摘要跟踪间隔**读取，默认 5 秒，可按位置修改。
读取失败时可以单独重试免费读取。

搜索批量读取已有的摘要，不刷新摘要，也不选择模型。较大的结果集会继续读取后续窗口。
每个来源保留当前权限和只读检查状态，因此另一组织暂不可用的来源不会阻止可读组织的提问。

摘要读取失败时，命中项会说明此视图的摘要不可用。**重试**只重新读取，不触发付费摘要，也不显示私密原因。

## 选择输入预算

模型摘要器的**输入词元**默认是 32,000，可为每种目标单独覆盖。可以提高到模型可用窗口减去输出所需空间；
指令和包装也占用输入空间。这是规划估算，实际用量仍以模型返回的数据为准。

答案额度以**词元**计，与目标的**输出字符数**分开。模型摘要器默认用 `answer_max_output_tokens` 为段落、
描述、标签和交接保留 1,024 词元；`title_max_output_tokens` 为标题保留 120 词元；
`goal_max_output_tokens` 为目标判断及理由保留 512 词元，均可在**摘要器**配置中修改。
段落和标题的字符目标仍分别默认为 600 和 80；它们约束返回的文字，不代表推理额度或实际计费用量。

已知会推理或推理信息未记录的模型，默认另留 `reasoning_tokens` 的 2,000 词元。
未启用调节选项，不代表上游模型不会推理。只有明确报告不支持思考时才取消这份预留，
允许选择的推理强度仍单独控制。推理词元设为零表示不额外预留。

优先考虑最近的有效条目。短条目完整保留，长条目公平分配剩余空间，在纳入更早内容前先保证必要细节。
提示词按从旧到新的顺序排列。未变化的条目在连续刷新间保留相同截取位置；空间满时，一批旧条目一起移出，
为新内容腾出空间。

**摘要详情**显示纳入、缩短和未纳入的源条目数；缩短的条目属于已纳入条目。私密或无权读取的内容在选择前已排除。
修改预算本身不会触发付费请求。

## 聊天补看与标题

**补看**使用打开聊天时捕获的未读消息范围。刷新这段补看仍使用同一范围，不会推进已读位置。
他人的未读位置不会变成你的未读位置。

未读范围为空时，摘要框说明没有新内容，不创建付费请求。主动选中的非空范围即使已经标为已读，
仍可以生成摘要。

**聊天标题**单独缓存，使用受输入预算约束的当前聊天文字。已经写好的群聊名称保持不变，自动标题不会替换它。
私密群聊和受限下级内容不会进入话题的共享摘要。

通过聊天查看权限打开已有内容时，沿用普通聊天查看的审计记录，不创建成员身份、聊天草稿或已读位置。
不可用的操作会在原有控件中保留原因。

## 提问和搜索结果

聊天使用**就补看提问**和**就聊天标题提问**区分未读消息与标题；各自将对应来源填入可编辑的提问草稿。

**就此提问**在原有提问面板中打开可编辑的引用和来源链接，固定在资源所属组织。
内容会追加到对应草稿；打开面板不会发送问题。检查草稿后，再使用**发送**。

帮助摘要随各语言文章一同撰写，不调用模型。内容搜索只显示命中资源已有的可读摘要，不为搜索生成摘要。
**就这些结果提问**按顺序引用当前可见的选择。如果结果来自多个组织，先明确选择要使用哪个组织的结果。
同一会话只使用一个根组织。仍在加载、已不可用或只能用于查看的来源，不会悄悄变成普通提问的输入。
