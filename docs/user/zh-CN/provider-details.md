# 选择和阅读提供方详情

提供方对它的凭据、模型访问、详情、模型和容器有各自独立的选择。数据源可以为密钥报告窗口、剩余余额、花费和重置，也可以为智能体程序的登录报告这些。卡片会写出**详情来自 <来源>**，并且只显示该来源和凭据保管者所知道的内容。它的金额使用提供方自己的单位。**Orch 计数**是令牌和价格表另外的账本。

委派能力的助手链接旁有默认折叠的**订阅**入口。展开后，可按您当前的提供方访问权限读取所选登录的已报告窗口、重置时间和观测时间；这里只读缓存，不启动程序或付费请求。无权读取的信息保持隐藏，未报告的使用量保持未知。账户整体观测不会变成助手结果的 API 价格或单次工作占比。

## 选择数据源

**添加提供方**先从接口开始：一个地址及其 API 格式，或智能体程序的登录。然后你给出凭据，以及能到达它的机器。示例填的是同一组字段。密钥之后在**登录和密钥**里添加。创建提供方不会等它的容器回答。它的页面先显示已保存的设置，而实时连接带来它的观测。

Gemini 的 [OpenAI 兼容 API](https://ai.google.dev/gemini-api/docs/openai) 使用
**openai-chat**。文档中的 Priority 和 Flex 分别使用 `priority`、`flex` 标识；在
同一个模型表单中启用该模型提供的层级并选择默认值。推理力度使用 `reasoning_effort`。
`extra_body.google.cached_content` 等 Gemini 专有字段同样使用嵌套请求选项规则、默认值
及每次使用的参数表单。

DeepSeek 的 [Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/)
也使用 **openai-chat**。文档中的推理力度及 `thinking.type` 可以设置模型默认值和每次
使用的覆盖值。该 API 没有声明推理速度层级选择器；模型规则中的 `service_tier: false`
会省略此字段，无需虚构 Fast 层级。新增字段使用现有请求选项模式及其 `default` 值；
所有提供商均依次应用端点默认值、模型默认值和本次使用的明确选择。

**请求默认值。** 在 API 端点的**高级 → 请求默认值**里设置请求选项。

- 请求本身的值优先。Orch 保留对模型、提示词、工具、输出预算和凭据的控制。
- 固定的标头、秘密标头和查询参数保留各自的字段。
- 自定义选项是配置，不能证明提供方支持它。
- 摘要器有同样种类的选项。先应用它端点的默认值，然后是设在它的模型上的默认值，最后是摘要器自己的选项。
- 对 OpenAI Responses，请用 ID `priority` 和标签**快速**打开模型的速度，并把这个 ID 选作它的默认值、请求选项、费率和限额。ID `fast` 是文档中的别名。用量会把实际报告的 `priority` 与所请求的分开保留。
- Anthropic Messages 使用 `speed: "fast"`，并把它需要的 beta 标头放在端点的标头里。Gemini、DeepSeek 和其他兼容的端点使用它们文档中的字段。选择一种格式并不会让模型获得它不提供的速度。

**详情来自哪里。** 在提供方的**设置**里，打开**详情来自哪里**。详情和模型各有自己的选择。

- **默认**是合适的读取方式：登录使用智能体程序的读取器；OpenRouter 或 DeepSeek 在使用密钥时使用已知的读取器（各自用密钥读取）；否则没有可选的详情。模型通常来自端点的列表。
- **程序**选择已经登记在保管凭据的机器上，或由它可信的模板自带的程序。它的字段是它自己的声明。秘密字段显示**已设置值；输入新值以替换**，绝不显示它的值。选择程序不会安装任何东西，也绝不会导出登录。托管的模板必须自带程序及其解释器。
- **地址**选择报告服务的 URL 以及它如何授权：**无**、**Bearer 令牌**或**名为…的标头**。授权值可以写入，但永远不能读取。例如，对虚构的 Acme 来源，用 `https://plan.acme.example/provider`。**把这个提供方的密钥发送到该地址**一开始是关闭的，在密钥发出之前会要求你确认主机。它不适用于登录。服务的令牌与提供方的密钥互相独立。
- **无**只保留凭据保管者的详情。对模型，**仅手动**让管理者输入用于路由的名称而不做发现。

以 `http://` 开头的地址会被拒绝，除非**允许未加密的上游**在这里允许它；这时它会被标为**未加密**。例如，内部服务 `http://plan.internal:41870/provider` 只有在打开这项策略时才能工作。调用从保管凭据的机器发出，所以那台机器的网络允许的主机，或它自己的上游列表，也必须允许这个主机。Orch 不跟随任何重定向。允许的地址按相同协议、主机和端口匹配完整路径段及其子路径。例如，`https://openrouter.ai` 允许该地址下的 `/api/v1`。

**保存**会读取来源的声明及其第一个结果。它支持的成员，或一条安全的错误，会显示在这个选择旁边。**添加提供方**表单显示同样的选择和同样的默认值。**添加来源程序…**在行内使用保管机器的程序登记，它返回的声明提供字段。见[构建你自己的提供方来源](../../development/extensions/providers/README.md)。

提供方的页面有六个部分：**概览**、**模型**、**登录和密钥**、**用量**、**设置**和**活动**。详情是一个简洁的标签和值的列表，带有每项被读取的时间。尚未读取的成员共用一行**尚未读取**和**刷新**。来源不提供的成员共用已报告详情下面的一行**未提供**，它的标题写出来源。缺少管理员密钥有它自己的说明，从未读取的详情绝不会被猜成零。终身使用量和近期使用量的数字会说明它们统计什么，例如轮次。**删除**保留在页面的菜单里，即使已保存的详情无法显示也可以使用。通常对访问和使用的检查仍然适用。

## 请求选项

在**登录和密钥 → 端点 → 高级**上，**允许的请求选项**按接口用 JSON Schema 设置规则。在**模型**上，使用组的**选项…**为该组里的每个模型设置同样的规则。模型的**编辑选项…**保留这个模型自己的规则。

一个字段的形式首先来自模型的规则，然后是模型保存顺序里最后一个组，再是更早的组，最后是端点。每一层仍然限制最终的请求。例如，端点允许 0 到 1 的温度，一个组把它限制到 0.5，模型从 0.25 开始：默认值是 0.25，请求 0.75 会被拒绝。模型更宽松的形式不能去掉它所在组的限制。这对智能体程序转发的调用和 Orch 自己发出的模型调用都成立。更改用于下一轮或下一次调用；正在运行的调用保留它开始时用的设置。

所属位置的一项设置决定一个模型在那里可以加入多少个组。它从 8 开始，可以提高。降低它不会动现有的成员关系，模型仍然可以被编辑或移出组。设为 0 则不允许新的成员关系。**添加模型**表单和模型的编辑器使用同一项设置。

要设置共享的规则，请把端点的通用规则放进**高级**，把 **frontier** 添加到它涉及的模型上，然后打开 **frontier → 选项…**，设置该组的规则。让模型自己的规则留空，就使用共享的形式。保存一个组会保留其他的组。格式错误的 JSON，或过期的修订，会让草稿连同错误保持打开。

## 会话选项

Codex 的**访问计划**也可用于转发的 API 端点，前提是该接口支持，并且提供方管理者已为模型启用对应计划。
在会话输入区的**访问计划**控件中选择，它位于**模型**和**强度**旁边，模型启用了计划时才会出现。修改从下一轮生效；该轮的租约在重试或重启后仍保留同一选择。
普通访问不会向 Responses 请求添加计划选择字段。提供方仅报告、尚未由管理者启用的计划不可选择。

管理者已为模型开启、但会话无法使用的速度、访问计划或上下文大小，仍有各自的控件，只是显示为关闭，并用几个字说明原因：智能体不提供、凭据没有留在提供方、环境或提供方属于另一种、提供方对该模型的规则把它排除在外，或**智能体功能**设置中对应的功能是关闭的。你有权解除时，控件还会给出对应的操作，例如**在智能体功能中开启**。

打开会话的**参数 → 请求选项**。通过 API 转发的会话按接口显示提供方开放的字段。
枚举值从列表中选择，固定值只读。使用程序自身登录的会话保留程序原有的参数控制。
提供方未声明的字段不会成为会话选项。

选择从**下一轮**起生效。正在运行的轮次保留它开始时用的设置，即使连接或提供方的容器重启之后也是如此。发出的请求使用你的选择经过转换后的结果，并且仍然必须符合端点、组和模型的每一条规则。例如，从提供方的列表中选的详细程度可以取代程序的值，但它不能覆盖固定的区域，也不能打开提供方已关闭的选项。切换模型可能意味着要重置它的新条目没有打开的选项。

当接口支持，并且提供方的管理者已经为模型打开了该程序时，Codex 的**访问**选择也适用于转发的 API 端点。请在输入框的**模型和推理强度**对话框里选择它。它从下一轮起生效，并在重试和重启期间保留在那一轮开始时用的设置里。通常的访问不会给 Responses 请求加上程序选择器。提供方只是报告的程序，在管理者打开之前保持不可用。

## 确认值

在**模型**中，**已报告的值**会在已保存的模型或建议上打开一张小的只读卡片。每个值都写明**来自供应商**或**来自目录**。只有供应商真正提供的值才得到第一个标签。目录的映射仍是一个建议，未知或较旧的来源会写**来源未确认**。卡片保留该模型观测的时间，没有时写**未报告时间**。较新的余额或套餐，不会给模型的旧报告标上日期。

- **供应商不同**指出报告的值与已保存的建议或选择不同的字段。卡片显示报告的值。已保存的条目和你的覆盖值保持有效，直到你编辑它们。
- 读取或刷新绝不会打开模型、速度、搜索或付费服务。
- 报告的最大上下文描述的是可用的内容。它与管理者向会话开放的上下文是两回事。
- 价格保留来源报告的小数。缺失的值不是零。

报告的**系列**可以在模型旁边提供**添加…组…**。它会打开模型的编辑器，提出这个成员关系并保留它的其他组。请审阅它，编辑或移除它，然后选择**保存**；**取消**不改变任何东西。只有供应商提供且已经符合组名规则的系列才会被提出。不会根据模型的名称猜测任何组。新的报告绝不会改变成员关系。组的数量限额仍然适用，包括零。需要空间时，请移除另一个成员关系或这个提议。打开的草稿会保留你选择的系列，即使之后的观测指出了另一个。

## 理解四种状态

| 卡片显示 | 含义 |
|---|---|
| 此来源未提供 | 来源从未声明这个成员，也从未报告它。 |
| 尚未读取 | 它声明了支持，但没有成功的观测。 |
| 未报告 | 它有意报告了空值或空列表。 |
| 一个值和一个时间 | 它在那个时间报告了这个值。只有真正报告了，零才是一个值。 |

例如，**剩余 12.50 USD** 是已报告的余额。之后省略了余额的读取，会保留这个金额及其旧的时间。有意不报告余额的读取则会清除它。新的窗口不会把旧的金额标成新的。来源出错会保留旧的值、它们的时间和一行安全的说明，**无法刷新 · 重试**。失败的详情查询绝不会把模型可用的凭据变成授权失败。

**刷新**读取当前信息和模型报价，新模型作为供管理者添加的建议。
组织的**添加时开启的内容**决定模型一开始可选的内容。**上下文、速度和访问计划**开启报告的上下文大小、速度和访问计划；**强度和上下文**开启上下文大小；**只有它自己说明的**保留模型自身的窗口和推理强度。网页搜索、缓存时长、推理模式、容量档位和请求选项需要单独配置。更大的上下文仍由每个会话选择。
没有填写窗口时，只要不超过模型已开启的上下文上限，Orch 就采用来源报告的最大上下文。目录和端点都没有提供可用值时，需要在保存前填写窗口大小。报告重置时间后一分钟也会读取。
紧凑说明优先使用约束窗口，再余额，再花费；没有可读信息就不能推测剩余额度。

## 程序退出

在**设置**里（提供方的管理者才看得到），**智能体程序进程**显示每个在用的智能体配置的当前状态。**上次程序错误**保留最近一次意外的退出及其时间，有的话还有程序给出的原因。即使配置重新上线，它也仍然可见。正在运行的轮次会被标为已中断，它的对话会记录原因。下一轮使用会话关于恢复历史的选择。

## 套餐预测

只要有足够的近期读数，每个窗口的仪表就会显示预测。**窗口**旁边的**随时间变化**会在**套餐**处打开提供方的**用量**标签页。实线是测得的使用量，虚线按已经看到的速度延续。**历史**显示每个间隔里增加的用量，并标出提前的重置。见[套餐窗口与预测](settings-and-usage.md#plan-windows-and-forecasts)。

当它的详情是私有的时，**用量**仍然可见，并写着**此视图的用量详情不可用**。你能读取的、没有套餐或历史的来源会写**此来源未提供套餐和历史**。需要管理员密钥的来源则保留那个原因。

## 使用重置

详情来源可以列出重置，并声明它可以把它们用掉。只有提供方当前的管理者，在浏览器里，才会得到**使用重置**。对话框显示确切的重置、有多少次、还剩多少，以及报告的影响。**取消**是默认选项；请有意选择**使用此重置**。不会使用任何模型，Orch 的限额保持原样。如果回复丢失，请求保持同一个身份，所以重复检查只会使用一次重置。

来源报告的限额，也可以让提供方在某个密钥上的工作处于暂缓状态。成功的重置，或让工作进入的后续观测，会在通常的权限和限额之下解除这个暂缓。

## 自己构建

[提供方来源概览](../../development/extensions/providers/README.md)，以及关于[详情](../../development/extensions/providers/facts.md)、[模型](../../development/extensions/providers/models.md)、[重置](../../development/extensions/providers/resets.md)和[密钥如何出示](../../development/extensions/providers/credential.md)的页面，都在帮助的**自己构建**部分。它们包含生成的结构、边界和错误，以及一致性检查所使用的确切的 Python 程序和地址示例。提供方的管理者选择已经存在的代码。为机器或可信模板编写它的人负责登记它。

## 请求选项规则

在**模型**上，打开模型的编辑器并选择**请求格式**。有文档的字段对规则有简洁的控件：**没有明确规则**、**限制**或**阻止**。

- 选择允许的值，而不选默认值；默认值是另一项选择。
- 标识符的规则可以固定提供方写下的文本，或去掉一个值。
- 这些规则收窄端点和模型的限制。文档里的某个档位不会仅仅因为目录列出了它就被打开。
- **原始 JSON** 保留自定义字段、智能体程序的规则和它不认识的模式关键字。格式错误的草稿会保持可见，直到你改正它。自定义的父级模式保持原始，而不会被简洁的控件取代。没有明确规则的属性，仍然可能被封闭的父级模式或另一层阻止。
- 当端点的格式声明了请求选项时，它们显示同样的控件。固定的公开标头使用标头映射，秘密标头保留它们单独的控件。**高级**保留其他名称和值。请求体的默认值与模式规则分开。

目录遵循各种请求格式，包括 [Responses](https://developers.openai.com/api/reference/resources/responses/methods/create)、[Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)、[Messages](https://platform.claude.com/docs/en/api/messages/create)，以及你为端点配置的扩展。有文档的字段并不证明某个模型支持它。

## 服务后端

在 API 提供方的**设置 → 服务**中，Orch 列出为它已保存的端点声明的服务。发现会让每个服务保持关闭。**编辑服务**让提供方的管理者打开其中一个，保留它声明的组或选择服务组，并以 Orch 点数保存一个可选的价格。保存这些选择不会开始搜索、读取页面或发出模型请求，也不会为任何会话选择后端。在它的运行时上不可用的服务，会把原因保留在控件旁边。

目录价格是以其原始货币计的估算。你保存的以 Orch 点数计的价格就是 Orch 计算的内容，供应商报告的总数保留在旁边以便比较。清除自定义价格会带回目录的估算。编辑会保留配置里的其他服务和较晚的字段。过期的提供方修订会被拒绝，这样就不会覆盖其他管理者所做的更改。

会话只有在它的能力被有意设为**服务**，并且它的后端指向已打开的服务之后，才使用付费后端。提供方的**使用**、允许的服务和模型列表，以及按用途划分的限额，在每个请求上都适用于原来的那个人，或开始这项工作的程序。提供方的模型列表和服务列表保持独立。**未设置**保留程序的默认值，并且不选择付费的后备。

## 直接调用模型接口

密钥提供方的**设置 → 转发**默认关闭。在模型选择器中开放准确的已启用模型，再开启转发。独立的**转发**权限使用与“使用”相同的完整模型、推理强度和部署方式条件；普通“可使用”不会授予转发。独立 SDK 调用没有经过确认的机器或环境，因此无法使用带位置限制的授权。订阅仍通过普通线程使用。

将 **SDK 地址**复制到 SDK 的基础地址，并使用 Orch API 密钥认证。OpenAI 兼容 SDK 使用其 API 密钥参数；Messages SDK 使用其 bearer/auth-token 参数。提供方的模型密钥始终留在连接的保管机器上。基础地址支持 `/responses`、`/responses/compact`、`/responses/input_tokens`、`/chat/completions`、`/embeddings`、`/v1/messages` 和 `/v1/messages/count_tokens` 以及 `/interactions`；模型列表仅显示已开放且调用者获准使用的模型。这些请求不会刷新提供方观测。

调用通过现有原生转发器逐段传输。相同的端点、分组和模型选项声明会在上游请求前约束调用。未开放的模型、未声明的选项、已耗尽的用量上限、不可用的保管机器或已关闭的转发会按实际原因拒绝调用。用量归于调用者，记录在**用量 → 转发**，来源为 Orch；用途列表为空的上限也包含转发。公开请求不携带提供方凭据，请求和响应内容不作为服务端文件保留。

系统设置 `providers.relay_concurrency`、`providers.relay_request_bytes`、`providers.relay_idle_secs` 和 `providers.relay_retry_ms` 分别控制排队准入、请求大小、静默时间和传输重试。`jobs.io_timeout_secs` 提供调用的原生工作总时限。读取端断开会结束其命令。SDK 重放请求会产生新调用；运行时崩溃后，Orch 不会自动重复可能已经付费的原生调用。


请求格式中的**通用**通过相同的端点、模型分组和模型层，在 `request_options.common` 中统一声明缓存与结构化输出规则。SDK 调用仍使用其接口的原生字段。显式线程选项使用 `provider_options:common`，与格式专用选项设置同一值时以通用选项为准；原有规则和已启用的限制仍然适用。接口无法表示成员或保留时间时，会在模型工作开始前指出具体项。仅设置结构名称的嵌套默认值不会启用结构化输出。新的接口实现通过同一协议契约提供其功能映射。
