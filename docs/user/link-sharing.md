# Copy links and share viewing when sending

Copy link makes an address for a person to open. Copy reference makes the form an agent can read, including an exact message, turn, file or selected lines where available. Sending a link can offer the ordinary viewing access that its actual recipients are missing.

## Where

Open a document, chat, thread or resource from [navigation](/) or [Everything](/everything), then use its menu. File and code selections offer a link to those lines. The reference card shows its readable home path and, for things you manage, the current Sharing summary and Share action. A person's card shows visible roles in their organizations.

In a chat or thread composer, inspect **Share viewing with N people and M agents** before Send. The people count opens the shared people list; the agent list names the actual recipients. Personal [Interface settings](/settings/interface) contains **Share viewing when sending links**. A place's sharing policy can govern the default.

## Example

Paste a document link into a group chat. Two readers already have access and one does not. The composer offers the missing person, rather than sharing with everyone again. Keep the switch on to send with the offered viewing grant, or turn it off to send the reference alone. Writing or previewing the draft makes no grant.

## What to expect

Send checks the current recipients, policy and normal grant choices again. A changed audience asks for review. A partial result keeps confirmed grants and identifies unfinished ones; review the remaining action before trying again. An accepted restricted receipt is still an accepted write.

An unknown recipient baseline is not treated as proof of missing access. A group-chat choice can require participation; the composer discloses it before sending. Giving people ordinary viewing access and giving an agent its permitted parts use their usual sharing controls. An unavailable exact reference stays unavailable rather than guessing a message number.
