# 模型调用恢复

模型调用失败时，Orch 会遵循第一条匹配的规则：等待并重试、继续、切换到另一个提供方或模型，或者把这次失败留给人处理。本页说明如何设置这些规则、规则运行时会话显示什么，以及如何制止不断重复的失败。

## 设置规则

1. 打开位置的设置，选择**调用恢复**。
2. 打开规则所在的行进行编辑，或添加一条规则。
3. 用**条件**、**原因**、**用途**、提供方和模型缩小规则的范围。要匹配提供方自己的消息，请使用**包含文字**、**正则表达式**或 **HTTP 状态码**。文字匹配不区分大小写。
4. 按它们应当运行的顺序添加步骤。行菜单可以调整或移除规则和步骤的顺序。
5. 选择**保存**。**取消**会让规则保持原样。

规则依次从系统、组织、项目或文件夹，再到话题继承下来。继承了锁定值的位置不能更改它。第一条匹配的规则处理这次失败，所以请把具体的规则放在通用规则之前。列表为空，则每次失败都留给人处理。

可以编辑的默认规则：

- **提供方繁忙**和**无法连接提供方**：最多重试三次。第一次暂停一分钟，之后每次暂停时间加倍。提供方给出的重试时间优先。
- **请求被拒绝**：最多继续三次。
- **已达限额**：在已知重置时间时，等到重置。
- **会话丢失**：在运行中会话的机器重新可达时，继续它一次。
- **未获授权**和其他所有失败：等待人处理。

## 选择候选项

要切换到另一个提供方或模型，请在规则里添加**故障转移**。在同一字段中选择提供方、模型或相应资源池，并按需选择智能体配置。这些选择显示与其他模型选择相同的用量和负载卡片。

- 只有规则里列出的候选项才能运行。Orch 绝不会选择规则没有指名的提供方。
- 候选项运行时，被恢复其工作的那个人仍然必须被允许使用它。不可用或不被允许的候选项会被跳过，会话会说明原因。
- **参数**接受模型或智能体程序支持的选项。它不能授予访问权限，也不能打开位置所禁止的东西。
- 嵌入的候选项必须保持相同的模型和相同的向量大小。否则它的向量无法与旧的向量比较，这个候选项就会被跳过。

资源池按自身策略选择尚未尝试的确切成员，并在重放或重启后保留这次选择。提供方池保留原请求的模型或服务要求。选择始终限定在当前成员内，同时遵守资源池尝试预算及调用方的重复保护；耗尽后等待人工处理。

启用模型或提供方池也会审核其普通默认行为：**产生可见效果之前改用下一成员**。此步骤由调用恢复负责，必须已有确切的原生命令终止回执，且没有可见效果。人工编写的恢复规则优先，包括空规则列表。未确认的启动始终保留在原命令中等待核对。查看资源池不会发起恢复尝试或付费请求。资源池的**立即重试**只解除其自身暂停，并保留共享失败证据。

在同一个提供方和智能体配置上更换模型，会在智能体程序支持的地方保留会话。不同的提供方或配置使用常规的切换方案，并带上你选择的历史。被阻止的切换需要处理。

**故障转移之后**设定接下来发生什么。默认情况下，会话在下一轮、它自己的选择已经就绪时，回到它自己的选择。选择**留在候选项**则保留候选项。

对于摘要或审核调用，如果目标提供，候选项保留原调用的请求格式，否则使用目标的补全格式。上下文固定了格式时，候选项编辑器会显示这个格式。通用规则可以为不同格式的调用服务：它写着**来自原始请求**，并显示**原始 JSON**，直到你选择一个预览。选择预览只会改变编辑器，不会给已保存的规则增加任何东西。

## 恢复过程中

会话的实时行会写出失败、下一步操作、已知时的等待时间和尝试次数。模型标签显示实际运行的模型。重复的失败使用一行带有尝试次数的错误。每个自动步骤会留下一行历史，带有它的规则、当时记录的尝试限制和时间。

丢失会话所在的机器离线时，实时行会说明它在等待机器回来。Orch 重启后，这次尝试仍然保留，**停止重试**仍然可以拦住它。

你可以做什么：

- **立即重试**会把已安排的尝试提前。它仍然会检查你当前的访问权限和限额。
- **停止重试**会停止今后的自动尝试。它不会撤销已经完成的工作。已被接受的切换有自己的**取消**。在切换过程中停止重试，会阻止后续的输入，并保留回到原来选择的过程。
- 需要处理时，横幅提供**重试**、**继续**和**切换**。**重试**和**继续**需要对会话的参与权限。**切换**需要管理权限。
- 会话在调用恢复中等待时，请使用它的实时控件或横幅。失败那一轮的**重试**保持可见但被禁用，并说明原因。等待结束后，失败或中断的轮次可以从历史里重试。更早的已完成轮次上的**重试**保持禁用。
- 已停止的恢复会在横幅里保留它的原因和操作。只能查看会话的人仍然可以阅读原因和本页。

因为它的提供方、模型、智能体配置或环境被关闭而停止的轮次并没有失败，所以恢复规则不会重试它，也不会发送**继续**。当你重新打开这个资源时，**运行等待的消息**会通过一条来自原作者、可见的**继续**恢复已开始的工作。尚未开始的轮次运行它原来的输入。此选项关闭时，队列保持暂缓，直到有人使用**继续**或**恢复**。

## 停止重复失败

**重复限制**和**重复窗口**约束同一种失败在一个会话里被自动恢复的频率。默认是五分钟内恢复三次。超过限制后自动处理就会停止，包括对保留了部分回答的轮次。横幅显示种类、次数和窗口。把**重复限制**设为**关闭**，就完全停止自动恢复。

**停止时通知**默认关闭。打开后，重复的失败会向会话的所有者发送一条汇总的收件箱通知。打开它可以查看会话并决定怎么做。规则、限制和通知与位置的其他设置遵循同样的继承和锁。

## 自动工作与权限

如果失败的轮次没有保留回答，也没有启动任何工具，恢复就会再次运行原来的输入。如果它保留了回答或启动了工具，恢复则会添加一条可见的**继续**输入。运行中会话的丢失也使用**继续**，因为程序可能做了它无法报告的工作。如果会话从未确认这一轮已开始，就由人决定如何处理等待中的输入。

- 输入把原作者作为发送者，它的标题写着**由规则自动发送**。提示写出规则和尝试，历史行说明它为什么继续，并链接到规则。
- 它的尝试限制是它运行时记录的值。之后对规则的编辑不会改变这段历史。
- 编写规则的人不是发送者。

自动工作保留原输入发送时所带的限制，Orch 在行动之前会再次检查作者的访问权限。被撤销的令牌或登录会停止自动工作；以更宽权限打开的浏览器无法取代它。每次被提供的尝试都计入它所服务的工作的那个人，用量记录会写出提供服务的提供方和模型。

## 摘要与描述

摘要、自动标题和标签，以及交接摘要，使用同样的规则，**用途：摘要**。它们的调用使用编写设置的那个人当前的访问权限。恢复保留同一份要摘要的工作，并分别记录每次模型调用。交接摘要的等待显示在切换作业里。如果它的链条无法继续，切换会退回到常规的记录。

已停止的摘要、标题或标签更新会在它的设置里显示**调用恢复需要处理**。阅读原因，修复规则、访问权限或模型选择，然后再请求自动值。缺少重置时间需要人处理：Orch 不会编造截止时间。提供方或模型被关闭的自动值会带着这个原因等待。这不是失败的尝试，它被关闭期间不会向它发送任何请求。

这些规则涵盖 Orch 自己发出的模型调用。智能体程序在内部进行的审核，也遵循该程序自己的控制。

## 能力回退

同样的规则涵盖**网络搜索**、**页面获取**和**生成图片**。**能力不可用**表示当前的智能体程序、登录、模型或已打开的服务无法提供这项能力。**程序默认**保留程序自己的行为，不添加隐藏的服务或回退。

1. 在**用途**下选择这项能力。
2. 添加**故障转移**，并选择**能力服务**作为目的地。
3. 选择提供方，选择它如何运行这项能力，并指定模型或服务。
4. 添加后面的步骤，例如**等待人处理**。

通过 Orch 的模型工具、提供方 API 和另一个程序的会话，都是同一条规则的明确候选项。使用候选项之前，调用会检查当前的访问权限、已打开的服务和限额。默认不设置付费的回退规则。

例如，为**能力不可用**设置一条规则，**用途：页面获取**。选择提供方的页面获取服务作为第一个候选项，**等待人处理**作为下一步。会话的**参数**视图会预览这条规则及其适用的范围。你读不到的提供方保持不具名。无法使用的候选项会连同原因被跳过，下一步继续。如果候选项因为别的原因失败，链条继续并记录那个原因。除非**故障转移之后**写明要留下，已完成的调用不会改变下一个独立轮次的原来选择。

更长的链条可以先重试两次，然后是一个指名的图片服务，再是第二个图片服务，最后是一次等待。链条结束时，会话会停止并显示**没有剩余的恢复步骤**。重复限制和当前的权限仍然适用。能力不可用，绝不是去寻找另一个提供方或向它收费的许可。

## 暂停的网页服务

托管的**网络搜索**或**页面获取**调用，在它的规则要求人处理，或它报告的重置时间晚于这次调用的截止时间时，会立即结束。结果告诉智能体：服务已暂停，并说明原因，以及已知的重置时间。它不会声称搜索没有结果或页面已读取完成。只计算暂停前实际测得的工作。

会话的恢复行会写出被暂停的服务。**恢复服务**会为下一次调用解除暂停。它不会重新运行已经关闭的请求，也不会添加输入。到了报告的重置时间，暂停会自行结束，下一次调用会经过通常的访问、策略和限额检查。等待人处理的暂停会一直保持，直到对会话有参与权限的人恢复它。旧的单个工具请求没有控件。

继承的值和位置消耗了什么，见[设置与消耗](settings-and-usage.md)；等待送达智能体的工作，见[消息队列](message-queue.md)。
