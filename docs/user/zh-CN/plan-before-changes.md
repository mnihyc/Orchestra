# 计划与目标

## 规划一轮工作

打开输入框审批模式旁的**计划**，再发送工作。代理先阅读并提出计划，然后才能修改。
默认关闭；位置可设置并锁定 `thread.plan_first`。只有支持计划的代理程序才显示此控件。

计划和审批模式独立。规划不会选择询问、自动或绕过。继续执行沿用界面显示的审批模式。
该模式的边界见[审批如何工作](how-approvals-work.md)。

## 回应计划

阅读计划卡片。**继续执行**让代理按输入框中显示的审批模式实施。代理程序决定如何
接收这一决定，Orch 会记录回应者。

**继续规划**把你的修改意见发回，要求修订，不批准实施。普通工作中的计划清单也会
实时更新；应先看卡片状态，不要把任意清单当成正在等待回答的提案。

## 谁能回应

默认有权驱动线程的人可以回答。位置可限制为所有者和管理者。仅查看的人能读计划，
不能继续执行。仍会检查当前访问权和模型使用权；规划不允许花费他人的提供方额度，
也不授予修改环境的权限。

## 内置程序

### Codex

继续执行时，会在回应者名下加入可见输入 **Implement the plan.**。

### Claude Code

继续执行会回答待定的计划请求，并恢复线程的审批模式进行实施。

### DeepSeek Harness

当程序及其已检查版本声明支持规划时，才会提供该功能。计划卡片与审批模式保持独立。
## 目标

目标让代理持续处理一项工作，直到完成。由 Orch 来运行，对所有代理程序一样；程序自带的目标模式保持关闭，
因为它会启动 Orch 没有检查过的回合。

## 设定目标

输入 `/goal` 和完成时应成立的事，例如 `/goal npm test 退出码为 0`；或在线程的 ⋯ 菜单中选择**设定目标…**，
分别写下**目标内容**和**完成条件**。**限额**（轮数、分钟、额度）默认不限；位置可以设定并锁定。
**结束时通知我**不勾选就不通知。

目标工作中、已暂停或已停止时，`/goal` 会打开已保存的内容，线程的 ⋯ 菜单会提供**编辑目标…**。
刷新页面后，目标行和操作仍然保留；达到限额时，先提高限额再点**继续**，也可以**清除目标**。

## 目标如何继续

每一轮结束后，Orch 统计用量，并以你的名义开始下一轮，所以它要通过你的消息要通过的所有检查：用量上限、
队列暂缓、审批和恢复。有问题、审批或计划在等人，队列被暂缓，或线程被阻塞时，它会等待。输入框上方的一行
显示**工作中**、**等你处理**、**已暂停**、**已达成**或**已停止**，以及已用的轮数、时间和令牌。

对话大纲会用**完成条件**标明目标回合，刷新页面后也能找到对应的工作。

## 达成与证据

代理用它的目标工具汇报：工作中、已达成（附证据）或被卡住。位置有摘要模型时，由它对照**完成条件**核对证据；
“尚未达成”会带着理由开始下一轮。没有摘要模型时，以代理的汇报为准，对话里会这样标明。代理被卡住时，
目标暂停，并说明它需要什么。

## 限额与停止

设定了的限额会停止目标，并说明是哪一项。在**编辑目标…**中提高限额，再点**继续**。**暂停**会暂缓目标，
停止正在运行的一轮也会暂停它，把它排队的一轮从队列取出同样会暂停。**清除目标**会移除目标；对话保留它做过的事。

无法使用 Orch 工具的程序没有办法汇报目标进展，所以它的目标会一直进行，直到达到限额或你暂停；悬停在状态标签上可看到说明。

## 谁能设定目标

能驾驭该线程的人可以设定、暂停、编辑和清除目标。设定目标还需要你自己能使用该线程的模型，因为每一轮都用你的
权限运行。每个操作都会记在对话和审计记录里，并写明是谁。

## 计划与目标

打开**计划**时，目标的第一轮先做计划；点**继续执行**才开始工作。
