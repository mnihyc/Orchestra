# 阅读和刷新摘要

摘要是会话、话题、文档或聊天旁边的一小段文字。它的状态、你能阅读的摘要器，以及上次成功更新的时间显示在一起。描述仍然是某个人有意写下的文字，摘要绝不会改写它们。

## 阅读状态

- **最新**与所选的来源一致。
- **已过期**表示来源改变之后仍保留较早的段落。
- **正在更新**表示请求已排队或正在运行。之前的段落保持可见、可阅读。
- **失败**保留上一次成功的段落，并显示问题。
- **还没有摘要**表示还没有生成过任何段落。
- **没有摘要器**表示没有选择你可以使用的生成者。已经存在并且可以阅读的段落仍可能保留。

打开**摘要详情**，或对聊天打开**补看详情**，可以看到所选模型声明的基础费率。缺失的费率保持未报告。这些费率是报价。**用量**页面显示调用真正用了多少。**参数**打开时，会话的摘要仍显示在对话上方。在消息较早的版本里，**参数**会说明实时摘要并不描述那段历史。它不会在那里加载或刷新当前的摘要。

## 刷新与默认值

**刷新摘要**会以你的身份请求一次更新。打开页面或搜索绝不会请求付费的摘要工作。你的刷新属于你，遵守你对提供方的**使用**权限、你可以使用的模型以及适用的用量限制。用途为**摘要**、对象为**成员**、划分为**每人**的每周限额，分别约束每个人使用摘要的量。

- 如果刷新的确认丢失，重试**刷新摘要**会继续待处理的那个请求。确认之后，对失败的读取点击**重试**只会重新加载摘要。你之后有意做的刷新是一个新的请求。
- 对于你自己的刷新，不必设置自动摘要器。Orch 会在你当前的访问权限、允许的列表和摘要限额之下，使用被允许的 API 模型，而不会打开自动化。如果没有可以使用的模型，输入框会说明原因。

### 配置摘要器

打开**设置 → 自动化 → 摘要器**，点按铅笔编辑此位置的选择。先选择已注册的摘要器。
选择**一个模型**时，可以按名称选择已启用的 API 模型或受支持的订阅程序。设置写入者需要允许其他工作的提供方使用权限。
**回答词元数**和**上下文词元数**在设置自己的数值之前显示内置默认值。
**请求选项**和**各字段的指令**只在需要时展开。提供方或模型无法使用时，会在字段旁说明。
其他已注册类型显示其声明的配置字段；配置模型表单无需手写类型名、提供方标识或 JSON。

**此处不设置**移除此位置的选择，恢复继承；**以 JSON 编辑**显示原始值。
本行的**保存**一次写入整个草稿，**放弃**恢复已保存值。按另一行的开关或筛选会保留此草稿，不会保存它。
需要自动刷新时，再单独启用相应的**摘要目标**；保存摘要器本身不会启用自动任务。
标题和标签也只在各自的自动化选项选择摘要器时才使用它。

确认的值存放在服务端数据库中，保留数据库更新程序时也会保留这些设置。
移除此位置的覆盖会恢复继承，不会删除上级设置。执行摘要时，系统重新检查提供方使用权限、模型可用性及用量上限。

**摘要对象**的每一行都有**自动**开关。开启后，**触发时机**、**最多每隔**、**读取至多**和**写入至多**
在设置自己的数值之前显示默认值。该行的**保存**和**放弃**仅影响自己的草稿。

为单个文档设置时，打开**操作 → 摘要选项**。保存此文档的选择，或用**使用位置默认值**恢复继承。
保存选项控制之后的事件，本身不请求摘要。通过 API 发起个人刷新时，可以为这次请求选择允许的模型，
而不更改自动摘要的默认模型。

没有你设置的间隔时，会话使用 120 秒，话题 900 秒，文档 300 秒，聊天和聊天标题 300 秒。话题里的更改会累积许多会话的变化。文档的编辑和聊天的消息通常是成批到来的。你为触发设置的共享间隔会覆盖这些默认值，某一种类的间隔会覆盖共享的间隔。**摘要选项**显示生效的间隔，而不会把它变成存储在文档上的覆盖值。

自动任务和个人请求的模型生成器都会保留完整的后端选择。受支持的程序后端在执行者拥有的普通私密辅助会话中运行，并遵循输出额度和当前来源检查。原生用量仍计入选定账号；程序不可用时不会自动改成 API 账单。分享辅助会话历史时，需要确认其中包含复制的来源材料。任务结束后，提示词查看器仍会检查提示词的原始来源。

对于一份文档，请打开**操作 → 摘要选项**。保存你自己的选择，或使用**使用位置默认值**重新继承。保存选项控制之后的事件，它本身不会请求摘要。通过 API 的刷新可以指定一个对那次个人请求被允许的模型，而不改变自动的默认值。

单次刷新请求可以指定允许使用的完整后端，包括受支持的订阅程序及其执行位置和选项，不会更改自动任务的默认值。

首次调用模型前来源变化时，Orch 会免费重新读取来源并重建提示词。**摘要重新读取次数**默认允许三次重复，
零表示不重复。内容持续变化时会明确说明。调用模型期间来源变化时，回答不会作为最新摘要发布，也不会自动
再次调用模型。摘要框会保留原有段落并标记为待更新，说明来源变化，并提供**重新生成摘要**操作。

个人主动刷新无需先配置自动摘要器。未指定模型时，系统按你当前的提供方权限、模型允许列表和摘要用量上限选择可用的 API 模型，
不会因此启用自动任务。没有可用模型时，摘要框会说明原因。

**已安排**显示实际的最短间隔或恢复等待原因及到期时间，原摘要仍可阅读，主动刷新仍需明确点击。
免费读取等待实际到期时间；已可运行或正在运行的任务按**摘要跟踪间隔**读取，默认 5 秒，可按位置修改。
读取失败时可以单独重试免费读取。

搜索读取已有摘要，不刷新摘要，也不选择模型。显示更多结果时会继续读取相应摘要。
每个来源都按你当前的访问权限检查，另一组织暂不可用的来源不会阻止你围绕可读结果提问。

摘要读取失败时，命中项会说明此视图的摘要不可用。**重试**只重新读取，不触发付费摘要，也不显示私密原因。

## 选择输入预算

在使用模型的摘要器里，**输入令牌**从 32,000 开始。目标可以覆盖它。你可以在预留输出之后，在模型的窗口之内提高它。指令及其框架也会占用输入的空间。这是用于规划的估算，**用量**仍然显示模型真正用了多少。

答案额度以**词元**计，与目标的**输出字符数**分开。模型摘要器默认用 `answer_max_output_tokens` 为段落、
描述、标签和交接保留 1,024 词元；`title_max_output_tokens` 为标题保留 120 词元；
`goal_max_output_tokens` 为目标判断及理由保留 512 词元，均可在**摘要器**配置中修改。
段落和标题的字符目标仍分别默认为 600 和 80；它们约束返回的文字，不代表推理额度或实际计费用量。

已知会推理或推理信息未记录的模型，默认另留 `reasoning_tokens` 的 2,000 词元。
未启用调节选项，不代表上游模型不会推理。只有明确报告不支持思考时才取消这份预留，
允许选择的推理强度仍单独控制。推理词元设为零表示不额外预留。

优先考虑最近的有效条目。短条目完整保留，长条目公平分配剩余空间，在纳入更早内容前先保证必要细节。
提示词按从旧到新的顺序排列。未变化的条目在连续刷新间保留相同截取位置；空间满时，一批旧条目一起移出，
为新内容腾出空间。

**摘要详情**报告来源中有多少条目被包含、被缩短和被舍去。被缩短的条目算在已包含的数量里。私有的材料以及你无法阅读的材料，会在这个选择之前被排除。更改预算本身不会请求付费的工作。

## 聊天补看与标题

**补看**涵盖你打开聊天时捕获的未读消息范围。刷新这份补看会保持同一个范围。它不会推进你的阅读位置，别人的未读位置也不会变成你的。

未读范围为空时，摘要框说明没有新内容，不创建付费请求。主动选中的非空范围即使已经标为已读，
仍可以生成摘要。

**聊天标题**单独缓存，使用受输入预算约束的当前聊天文字。已经写好的群聊名称保持不变，自动标题不会替换它。
私密群聊和受限下级内容不会进入话题的共享摘要。

对未读消息使用**就补看提问**，对标题使用**就聊天标题提问**。每一个都会在问一问草稿里打开它自己的来源，你可以编辑。通过聊天检查打开的已存储内容使用通常的检查审计。它不会创建成员关系、聊天草稿或阅读位置。被关闭的操作会把原因保留在控件旁边。

## 提问和搜索结果

**就此提问**会在资源所属的组织里，打开已有的问一问面板，带有你可以编辑的引文和引用。它会添加到匹配的草稿里，打开它不会发送问题。请先检查，准备好之后再使用**发送**。

帮助里的摘要是随每篇翻译的文章一起写好的，不使用任何模型。内容搜索在有可读摘要时，会显示命中的摘要。它绝不会为搜索生成摘要。**就这些结果提问**会按原样、按它的顺序引用可见的选择。出现多个组织时，请选择使用哪个组织的结果。一段对话只保留一个根组织。仍在加载、不可用或只能被检查的来源，不能悄悄变成问一问的普通输入。
