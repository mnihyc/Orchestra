# Browser view

The browsers of an environment, and one of them in front, beside a thread (the view `browser`) and as the
Browsers tab of the environment's page. What is real: the list (open browsers, the thread's agent's first,
then the profiles none runs on) kept current by the environment's feed of browsers; "Open a browser…" with
a profile of the list or a new one, how it starts and where it begins, the sentence about sign-ins, and
joining said as joining; a profile renamed and deleted with its name typed; each way of being off and
nothing found, with what was looked for and Look again; the page drawn from the browser's socket, scaled
with its proportions kept and each picture acknowledged once drawn; Drive and Stop driving on sockets of
their own, pointer, wheel and keys in the page's coordinates, an input method's text and a paste as text,
Ctrl+Alt+Esc giving the keys back; the bar, the tabs and the menu; a dialog and a request for a file shown
to whoever drives; the reduced picture; who watches and who drives; a port's "Here in its browser"
(`portsBrowser`), and "Open" on the row of the agent's tool.

The browser list requires its installed-program facts. An answer missing `support` or `programs`
shows a translated local Retry; it does not claim that discovery found no program or enable Open.
A valid empty programs array still shows the existing no-browser/Look again state. The native live
feed may contain only browser/profile rows: it merges into a complete held projection and cannot
seed one before its HTTP capability facts arrive. Malformed later support cannot erase those facts.
Environment Tools keeps its section navigation outside each selected content boundary, so a failed
browser view leaves Terminal, Ports and the other tools reachable. Regression sources cover the
actual EnvironmentScreen/query, cold and warm feed shapes, Retry/Look again and picture faults in
EN/ZH and both themes; executable/rendered proof belongs to the integrator.

Not built: the small picture on the tool's row, the warning mark on the view's tab (the workbench's tabs
carry no mark yet), the picker of the environment's files for a request (a path is typed), and saying that
an agent works in the same tab (no wire fact says so). The fake world's browsers (`tests/doubles/browsers.ts`)
draw real JPEGs made there; the real server has not been tried from here.

- `socket.ts`: the browser's socket: frames both ways, the picture's header, reconnecting with a new ticket.
- `Picture.tsx`: the page as a canvas, and a person's hands while driving.
- `Front.tsx`: one browser in front: bar, tabs, picture, people, what a page asks.
- `Browsers.tsx`: the list, the ways of being off, the profiles' dialogs, and the one in front.
- `OpenDialog.tsx`: "Open a browser…" and joining.
- `View.tsx`: the view's registration beside a thread, the Ports entry and the tool row's Open.
- `store.ts`: what other screens ask of the Browser and VNC views.
