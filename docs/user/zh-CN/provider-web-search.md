# 提供方网络搜索

提供方可以把它的模型内置的网络搜索提供给智能体、摘要和目标检查使用。提供方的管理者决定打开哪些搜索模式，以及新的使用从哪一种模式开始。提供支持并不意味着打开它。

内置的网络搜索查找网络上的公开信息。Orch 给智能体用来搜索它们有权阅读的文档、聊天和会话的工具，是另一种能力。

## 在哪里

1. 打开[提供方](/resources/providers)并选择提供方。
2. 在**模型**上，打开模型及其选项。提供方的管理者打开它支持的模式，并选择默认值。
3. 打开会话的**参数**。会话在那里，在提供方的限制之内选择它的模式。
4. [用量](/usage)在请求的其他用量旁边，显示报告的搜索次数和设置的费用。

Codex 报告网页操作结束时，该操作的行立即结束，即使回答仍在继续。缺少用量证据时会添加未验证提示，
保留程序已报告的结果；若保留的结果证实失败，才将操作标记为失败。证据核实前，用量保持未知。
无法匹配保留结果的 Codex 托管搜索也遵循此规则。来源链接和成功的回答不能证明其搜索次数。

读取原生结果证据有独立的短等待时间。系统设置中的**原生结果等待时间**
（`agents.native_result_wait_ms`）默认为 2000 毫秒；程序配置可以在引擎的中断等待窗口内选择其他值。
读取超时会添加未验证提示，保留操作已报告的结果。

读取期间，其他会话及其静默计时器继续运行。等待会话的后续输入保留到达顺序。
**原生结果缓冲区**（`agents.native_result_buffer_bytes`）默认保留 8 MiB 待处理输入，程序配置可选择其他大小。
缓冲区满时，Orch 将可选的证据读取结束为未验证，并处理全部保留输入；不会丢弃输入，也不需要手动处理。
系统默认值在程序重新启动时生效。

**网页操作等待时间**（`agents.web_action_wait_secs`）将尚未报告结束的原生操作关闭，并提示原因。
默认值为 120 秒，可在所在位置的设置中修改，会话重新打开时生效。此操作只关闭该行，轮次继续运行；
之后真正到达的结束事件仍可更新同一行。以此方式关闭的操作不提供用量次数。


- **禁用**拿走托管的搜索工具。
- **缓存**在协议支持的地方，使用已建立索引的内容，不做实时检索。
- **实时**让模型在需要信息时进行搜索。

默认值仍然只是一个选择。固定的提供方选项会显示它的来源。

## 示例

协议兼容不代表每个模型都支持搜索。DeepSeek 文档明确说明 Responses 接口的 Pro 模型支持服务器端搜索；忽略搜索选项的模型不能算作实际运行了搜索。Google 的 OpenAI 兼容文档仅在 Images 端点列出搜索工具，没有说明 Chat 的搜索映射。Gemini 原生 grounding 可使用 Google Gemini Interactions 协议及 Gemini 原生端点，例如 `https://generativelanguage.googleapis.com/v1beta`。凭据通过 `x-goog-api-key` 提交。每次请求携带当前获准的会话内容，设置 `store=false`，保留原生签名步骤，不使用隐藏的远程历史。先在模型上启用实时搜索，再通过 `search_types` 选择 `web_search` 或 `image_search`。调用方的函数工具会保留。仅上游明确报告的 `grounding_tool_count` 提供搜索次数；未报告的次数保持未知。

## 配置托管工具

请先在提供方的模型上打开这些模式。端点的请求默认值就可以用名称 `web_search` 配置托管的搜索工具：

- **Responses** 支持搜索上下文的大小、按域名筛选、大致位置，以及通过所选模式的实时访问。
- **Messages** 支持搜索次数的限制、允许或阻止的域名，以及大致位置。

这些选项配置这个工具，并保留请求里的其他工具。对 Responses 端点，请求默认值可以写成：

```json
{"web_search":{"mode":"live","search_context_size":"low","filters":{"allowed_domains":["example.com"]}}}
```

对 Messages，使用它自己的选项：

```json
{"web_search":{"mode":"live","max_uses":3,"allowed_domains":["example.com"]}}
```

允许列表和阻止列表不能同时使用。一次使用选择**禁用**会覆盖默认值。端点的默认值配置的是智能体已经选择的工具；它们不会打开智能体程序没有包含的工具。摘要和目标检查通过提供方模型的同样限制取得它们所选的设置。

## 设置搜索价格

模型的费率和费率表接受**每次网络搜索的点数**。请用与令牌费率相同的点数单位输入价格。以美元计，文档中的基本搜索费用，OpenAI 和 Anthropic 是 `0.01`，DeepSeek 每次成功的搜索是 `0.00075`。搜索费用不适用于令牌所用的服务档位倍数。搜索令牌仍然可以计入模型的令牌费用。

次数和价格随每个请求一起记录。打开了搜索但缺少次数或价格的请求，它的总费用是未知的。重复的累计报告不是额外的使用。这些是根据设置得出的估算，不是发票。

有意选择的搜索引擎可以对每个请求收费，并对计费的结果另收一笔费用。Orch 会把这些声明的条款与真实的请求保存在一起。请求的结果数量和显示的引用链接，不会被当作计费的结果来衡量。如果缺少需要的次数，完整的估算保持未知。当引擎是自动选择的，或是内置的，价格取决于提供方，除非报告了总数。供应商的相符总数只替换目录的估算；你为提供方或在费率表上设置的点数价格仍然有效。

**什么算一次搜索。**

搜索费用可以叠加在模型的令牌之上。你看到的一次 **WebSearch** 工具调用，在后台可以包含多次搜索，所以看到一次并不等于计费的次数。缺失的次数是未知的。供应商相符的总数可以替换目录的估算，你设置的点数价格仍然有效，报告的总数保留在旁边以便比较。

- **使用直接登录时**，内置搜索的数量在每一轮结束时按模型报告。Orch 只记录一次增量，扣除已经记录在真实请求上的数量，并应用你设置的、与令牌价格和速度分开的单价。恢复的对话的第一个累计总数，在它先前的总数未知时设定起点，缺失的次数保持未知。被转发的连接保留转发器的计量。
- **使用 Codex 时**，独立的网页操作只有通过保留下来的成功结果才能证明用量。搜索操作算作网络搜索。打开页面或查找文本算作页面获取。空的搜索结果仍然可以是一次成功的调用。程序的结束事件及其分析计数器并不证明成功。失败或不匹配的尝试会显示出来，但不计数也不收费，缺失的证据保持未知。Orch 用程序经过验证的构建读取结果，不根据消息的文字去猜。重放或接管显示历史的结果，绝不会再次计费。
- **网页操作失败**（`native_web_action_failed`）表示保留下来的结果报告了失败。**无法验证网页操作**（`native_web_action_unproven`）表示结果、原所有者、模型或支持的格式无法匹配。该操作保留它的查询、页面和原始来源，原本已经完成的文本轮次仍保持完成。在该操作的原始视图下打开**完整输出**，可以阅读它的结果和报告的结果。
- **在用量 → 请求里**，**内置能力用量**写出这些合计，并链接到它们原来的轮次。它们不增加模型请求、令牌费用、尝试或延迟。报告的零仍然是零，未报告的模型令牌占比会写**未测量**。未知的单价保持未定价。

## 能力的运行方式

打开会话的**参数**并阅读**能力**。每一行都来自服务器所用的同样的声明支持和当前设置：模型的工具、程序的工具、所选提供方的服务，或另一个程序的会话。不可用的行会写出当前的原因，例如模型被关闭、模式不被支持、缺少访问权限或没有选择服务。如果程序没有报告它的默认值，这一行会写**程序默认**。

只有在你有权阅读时，才会出现提供方和每次调用的报价。报价保留它声明的货币和单位，缺失的价格是未知的。路线的预览不预留用量，也不允许之后的调用：当前的访问权限、提供方的设置和用量限制在调用运行时才检查。选择提供方的后端不会打开付费服务。把能力保持在**程序默认**，就保留程序当前的行为，或者在提供服务的地方有意选择服务。

例如，对搜索使用提供方服务的会话打开**参数**。**网络搜索**一行会写出那个提供方，以及它为每次搜索声明的价格。如果访问权限被收回，同一行会变成不可用并说明原因。Orch 绝不会悄悄选择另一个提供方。以后的扩展提供的能力，会根据它的声明出现在同一个列表里。

托管的搜索和页面获取使用位置的调用规则。配置好的重试保留工具原来的截止时间。配置好的回退会为每个指名的候选项再次检查访问权限、提供项的限制和上限。无法使用的候选项会被跳过，因别的原因失败的候选项会让同一个链条继续。成功的恢复会在会话里记录它的原因和规则，不会更改所配置的后端。每次尝试只记录它真正测得的用量。等待人处理，或重置超出了工具的截止时间，会返回暂停的结果。在智能体下一次调用之前，请使用会话的恢复操作，或等待报告的重置。

**会话中的 Claude Code。** 会话的**参数**视图在每项能力旁边显示所选程序的访问事实。Claude Code 的转发路径省略了仅限原生主机的 beta 选项、缓存的保活、托管模型的目录，以及它内置的 WebSearch 的引用和模式选项。这不会关闭普通的转发生成，也不会改变为会话选择的缓存时长。在**分离**安排中，它内置的 WebFetch 从提供方的容器读取页面，会话会显示这个位置。这些是对当前路线的说明。它们不是额外的权限或工具。

## 网页抓取

**页面获取**独立于**网络搜索**。

- **未设置**保留程序现在使用的页面读取器。
- **关闭**关闭这项能力。
- **内置**使用所选程序或模型声明的页面读取器。
- **服务**使用你选择的获取服务，并从下一个会话起关闭它声明的内置对应项。

打开托管的**网络搜索**不会打开托管的页面获取。

在组织层面，**网络搜索后端**选择提供方和模型，或该提供方的搜索服务和获取服务。API 后端的获取服务是可选的。没有获取支持的后端对页面获取保持不可用，Orch 不会通过返回搜索结果的片段来模仿它。提供方的管理者在提供方的**设置**里打开每项服务，并可以设置它的组和它以点数计的确切价格。调用运行时，智能体需要当前的**使用**权限、适用的每一项提供项策略，以及限制之下的余量。

例如，让**网络搜索**保持它选择的模式，打开位置的设置，把**页面获取**设为**服务**并保存。开始一个新会话来得到变化后的工具集。被读取的页面在与内置工具打开的页面相同的时间线卡片里，显示它的真实地址和返回的内容。**用量**记录页面获取的用途、真实的后端和报告的计费页面。它不会把搜索结果的链接算作页面。把**页面获取**设为**关闭**，即使较早的会话仍列出旧工具，也会阻止再一次付费获取。

## Codex 端点支持

有些 Codex 模型会自己发出单独的搜索请求。这样的模型需要声明了这种支持的端点，以及打开了搜索的模型。**缓存**、**索引**和**实时**只有在当前的解析提供它们时才会出现。没有所需工具的端点，可以使用你选择的搜索服务。保持**程序默认**并不会选择付费服务。

成功的独立搜索算作一次搜索操作。打开页面，或在页面里查找文本，是另一项页面操作。多个查询或来源链接不会产生额外的计数。失败或未经证实的回复，对这些数量保持不收费。只做了搜索的回复不提供生成令牌的计量。

当主模型没有内置搜索而有可用的托管后端时，Codex 通常的**网络搜索**控件可以提供**服务**。打开这个控件，或让它保持未设置，都不会选择付费服务。选择**服务**会关闭内置搜索，并在会话重新打开时生效。智能体配置的高级设置里的键 `web_search` 仍然是程序自己的选项：在提供方的限制之内使用**禁用**、**缓存**、**索引**或**实时**，并通过会话通常的控件选择托管的服务。

## Codex 模型详情

被转发的 Codex 会话从提供方里模型的条目取得它们的图片输入、上下文窗口和已打开的速度。模型自身的窗口，以及管理者打开的更大上下文，保持分开。并发的会话保留各自的模型详情。更改在会话打开时被接受，已经在运行的工作保留它的设置。

只接受文本的模型会把附加的图片作为文件收到，消息里带着它的路径，它查看图片的工具保持关闭。名称与内置 Codex 模型相似的模型，只有在端点声明了这种支持时才会得到它自己的请求方言。
