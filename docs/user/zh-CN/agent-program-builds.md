# 代理程序构建

系统管理员在**管理 → 代理程序**中管理构建。校验和来源与检查结果回答不同的问题：
谁提供了预期的程序内容，以及兼容性检查是否通过。设为默认构建不会改变这两项事实。

## 校验和来源

随 Orch 发布的构建使用发行版中的校验和；厂商渠道构建使用直接从厂商读取的校验和。
管理员也可以添加预期校验和，或导入在联网机器上收集、带入内网的厂商校验和列表。
导入的构建从**未测试**状态开始。

普通镜像只传送程序文件，不能通过自己的元数据确立预期校验和。
在内网使用时，先在外部收集厂商校验和，再由管理员明确导入。
导入命令显示列表的摘要，并将摘要记录到管理员审计中。

## 信任镜像

**信任镜像校验和**是系统设置，初始关闭。只有允许该镜像发布可执行构建时才启用。
这类构建标为**校验和来自镜像（并非厂商）**；兼容性检查通过后仍保留该标签。
关闭信任后，这些构建不能再被选择，也不会进行后台检查。

没有明确校验和来源的旧记录暂不可用，需管理员导入其厂商列表或明确添加预期校验和。
收集、导入和在内网提供文件的步骤见操作人员指南 `docs/operator/offline.md`。
