# 阅读通知和发送公告

## 阅读收件箱

收件箱记录 Orch 告诉你的事情。可选择全部、未读或提及，并按日期或位置分组。
打开一行可进入相关工作。标为已读后，可用撤销恢复原状态。通过分页控件查看更早的通知。

收件箱条目不授予原内容的访问权。权限变化后，私有细节可能不再显示。通知设置控制
向外投递；标为已读与暂停投递有不同作用。

左侧栏的“消息”显示当前根组织的个人未读聊天数，组织栏的未读圆点也使用同一计数。
即使树中隐藏了聊天，两处仍通过你的个人聊天状态更新。隐藏或未关注的聊天不计入；
在另一浏览器读完后，此处的计数也会更新。

## 选择何时接收提醒

位置旁的铃铛设置该位置的通知级别。默认沿用上级最近的选择。设置 → 通知列出例外、
免打扰时间、暂停和外部渠道。渠道完成自身配置后才可用；浏览器推送权限只对本设备
生效。投递和保留规则见[通知](settings-and-usage.md#notifications)。

## 发送公告

从组织、项目或话题打开公告。选择通知或里程碑、重要程度，以及全部线程还是活动线程，
再填写标题和正文。发送需要该位置的参与权限，已归档的位置不能发送。

发送前检查投递方式。下一轮会等待；引导在支持时加入当前轮；中断先停止当前轮再投递。
默认使用位置设置。后备方式决定不支持引导时怎么处理。“启动空闲线程”是每次发送默认
不勾选的复选框，勾选才会为本次公告启动轮次。`broadcast.wake_idle` 控制是否允许选择，
出厂开启；关闭后复选框禁用并说明原因。不勾选时空闲线程等到下一轮再接收。
这些选择影响代理工作，应一起确认接收范围和投递方式。

智能体使用 `announce` 或以线程为目标的 `send_message` 时，也须显式给出
`wake_idle: true` 才唤醒，省略为 false。接收话题禁止唤醒时，请求 true 会被拒绝并注明
`broadcast.wake_idle`。跨话题发送时，若任一接收话题禁止所请求的唤醒，整次发送被拒绝。
每个发送线程独立计数，出厂每滚动小时允许 12 条公告（`broadcast.rate_per_hour`）及
60 条向单个线程发送的消息（`broadcast.thread_messages_per_hour`），二者互不占用。
零表示禁止该类发送。仅面向关注者的里程碑不计入这两个额度。

## 查看结果

结果列出已投递、排队和跳过的工作。最近公告保留标题、正文、投递数量和时间，刚被
接受的发送也会立即出现。翻页可看更早记录。发送失败会保留原因；再次提交前先确认
已有结果，避免重复。

公告和代理的里程碑都保留在对话中。给代理的公告与给人的收件箱通知有不同接收者。
