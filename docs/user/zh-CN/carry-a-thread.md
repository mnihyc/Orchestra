# 将会话历史带给另一个智能体

在分叉或切换的计划里选择**携带**，即可带上你所选的对话。确认之前先阅读计划的历史方式。该方式取决于目标智能体程序的确切版本已被证明能导入什么。

## 查看传递方式

计划会写明三种方式之一：

- **内置导入**恢复智能体程序自己的对话。
- **中立导入**以共享格式带入已记录的轮次。
- **文件交接**把最近的上下文和完整的对话文件交给新的智能体。

当旁路会话的分叉包含它的第一轮时，计划还会统计创建该旁路会话时所捕获的父级对话。

**Codex。** Codex 会话把历史保存在程序自己的存储里，Orch 从不复制它。

- 在创建它的主目录里，以及环境连同它的卷一起移动时，会话用它自己的历史继续。移动后的环境在下次使用时才会打开会话，而不是在移动时。
- Codex 恢复会话时，会有一行安静的说明：它沿用会话开始时的常驻指令。对这些指令的修改会在下一个新会话中生效。这条说明并不表示该轮次失败。
- 要在某一轮用自己的历史分叉，Orch 先把这一轮的位置与程序保存的对话记录核对，该记录最多保存 32 MiB。包含的内容超过**内置分叉检查大小**允许的对话（除非位置另有设置，为 32 MiB）不会被检查。计划随后会像换到另一个主目录那样写**中立导入**或**文件交接**，并告诉你。
- 到另一个主目录（另一个环境、另一个凭据的主目录，或没有该卷的机器），Codex 无法完整交还它的历史。当你所选的每一轮都能放进该位置给新模型窗口的携带份额时，计划会写**中立导入**。否则写**文件交接**：能放下的最新几轮逐字带入，整段对话是工作区里的一个文件。传递的量受窗口限制，而不是受会话长度限制。

当某个程序的历史确实以文件形式传过去时（程序自己的导入，在机器之间），作业会显示已有多少字节到达 Orch，以及预计何时传完。取消作业会停止机器上的传输，并删除它的文件。中途失败的传输会让已到达 Orch 的部分保留一天。在会话没有变化时再次携带，只会发送其余部分。

## 检查另一个版本

在**管理 → 构建**中，**检查**会在隔离环境里观察确切的构建。程序自己的导入不可用时，该功能保持关闭，检查会记录原因。其他检查仍可通过。

- 对于导出历史的程序，当构建导出对话、导入全新的主目录并读回两个已完成的轮次后，导入才变为可用。
- 对于 Codex，检查在创建它的主目录里于第二轮处分叉一个对话，并在该主目录的副本中重新打开：下一个请求必须带上分叉之前的各轮，而不带之后的任何一轮。
- 修改配置的覆盖项不能打开一个尚未被证明可用的导入。
