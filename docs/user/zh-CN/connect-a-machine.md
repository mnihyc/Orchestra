# 连接一台机器

使用同一轮更新的 API、网关和连接器程序。帧格式版本不兼容时，会在建立会话前明确报告。
较大的模型目录和会话历史会自动分段传输。

## 1. 选择这台机器做什么

打开**资源 → 机器 → 添加**，然后选择角色。

- **环境**使用你登记的文件夹。
- **智能体**运行智能体。
- **提供方**保管模型凭据。

这三种角色共用一个连接器。**节点**是另一回事：它在 Linux 主机上创建托管环境，是单独的程序 `orch-node`。要在同一台电脑上同时有两者，请把它既添加为主机又添加为机器。连接器不接受**节点**角色。

选择你有权添加的位置。默认是你自己的组织，机器一开始只属于你私有：同在一个组织并不会让其他成员获得访问权。连接机器并不会共享它的全部文件夹。使用机器上某个文件夹的环境在 Linux 上可用。macOS 或 Windows 连接器仍然可以为它的其他角色连接。

## 选择网关

**添加机器**和**添加主机**的表单提供**网关**：**自动**，或已公布的某个名称。命令会把你的选择交给安装程序。

- **自动**从正在安装的机器上测量，选择测得往返延迟最低的网关。主连接重新连接时它会再次测量，连接期间也会测量；当某个网关严格更好时它会切换，并先等主连接和目标附加连接上的活动通道结束。浏览器不会测量这台机器的路由。
- 你选定的网关会一直保持选定，即使它不可用或已从目录中移除；选定的主网关也绝不会自行切换。要更换它，请在机器的本地控制台或安装程序里更改选择。重新登记时不带网关参数，会保留已保存的选择。移除一个已选的网关不会让机器变成**自动**。

机器的**连接器**卡片或主机概览会显示已报告的主网关以及它是如何选定的。选择**自动**时，它还会显示每个网关的测量值和测量时间。**未测量**不代表延迟为零。**刷新**读取最新的报告，并保留它原来的测量时间。

## 网关列表

系统管理员在**管理 → 网关**中编辑名称、区域和已验证的端点。一个固定的 ID 对应一个网关，多个端点地址可以是它的别名。区域是运营者的说明。更改名称或地址时，按 ID 保存的选择保持不变。编辑列表只是公布可选项，它不会安装网关，也不会移动已连接的机器。

编辑器会记住你打开时的版本。如果另一位管理员先改了列表，被拒绝的草稿仍留在表单里。请先**取消**、刷新并查看当前列表，再重新保存。

## 隧道网关

工具的隧道可以使用与连接器主网关不同的网关。两者不同时，会话会显示已附加并确认的网关，环境的**会话**行也提供每个会话的网关详情。共享一个环境并不意味着每个会话都用同一个网关。**连接中**表示附加仍在等待。**尚未报告**绝不表示首选的候选网关已经附加。打开**隧道网关**查看当前报告，用**刷新**再次读取。

当两台机器没有共同的网关可以连通时，屏幕会说明工作已保留，并列出它试过的网关及用安全措辞写出的拒绝原因。请确认这些机器能访问那些网关，再使用常规的恢复操作。

当两台机器都保留工具的原始套接字和字节时，后备方案可以在现有的一分钟宽限期内，通过另一个共享网关恢复工具的连接。它继续同一项工作，不会再次运行工具。如果状态缺失、票据过期、端口权限丢失，或没有可连通的共享网关，这条连接就会结束，并使用对中断工作的常规恢复。人的终端、浏览器和显示会重新附加。两个已保存的主网关选择都不会改变：被选定的主网关可以保持离线，而隧道在别处继续。接纳新的网关仍然需要 API。

### 配对测量

两台机器之间的新隧道使用两边测得往返延迟总和最低的网关。两组样本都必须足够新，才能用于实时连接，通常在 60 秒以内。测量缺失或过期时，使用执行端的主网关。**隧道网关**一行会显示选择、依据的规则、已知时的测量总和、每次测量的时间和样本的限制。缺失的测量始终显示为缺失。

继承的**隧道网关**设置可以让某个位置的新隧道固定使用**执行端网关**。它不会移动你为机器选定的主网关，不会改变已有隧道冻结的方案，也不会让字节经由另一个网关或 API 传送。共享的后备方案仍然把两端直接附加到一个可连通的网关。

## 2. 选择账号和运行方式

连接器以**你的账号**运行，无需 sudo，也无需管理员权限。它在你登记的文件夹里工作，与终端当前所在的文件夹无关。

| | 程序 | 数据 |
|---|---|---|
| Linux | `~/.local/bin/orch-connector` | `~/.local/share/orch-connector`（或在 `XDG_DATA_HOME` 之下） |
| macOS | `~/.local/bin/orch-connector` | `~/Library/Application Support/Orch/connector` |
| Windows | `%LOCALAPPDATA%\Orch\orch-connector.exe` | `%LOCALAPPDATA%\Orch\connector` |

- **用户服务**让它在 Linux 上通过 systemd、在 macOS 上通过 launchd、在 Windows 上通过登录任务保持运行。在 Linux 上，除非管理员允许用户服务在退出登录后继续运行，否则它会在你退出登录时停止。在 macOS 和 Windows 上，它在你登录期间运行。用 `orch-connector service stop` 和 `orch-connector service start` 停止或启动它。在 Windows 上，先运行 `& "$env:LOCALAPPDATA\Orch\orch-connector.exe"`，再执行 `service stop` 或 `service start`。
- **前台运行**会加上 `--no-service`（Windows 上是 `-NoService`）。对话框里的完整命令会不带服务地安装程序，并在终端里启动它，按 Ctrl+C 停止。如果你手动运行安装程序，请运行安装程序在结尾打印的、以 `run` 结尾的命令。请先停掉已有的服务。选择**前台运行**不会移除已有的服务。
- **另一个实例，需命名。** 多个连接器可以并排运行。填写**另一个实例的名称**即可得到独立的身份、数据目录和服务。命令会加上 `--data-dir`（Windows 上是 `-DataDir`）。之后对这个实例执行的命令，例如 `service stop` 或 `service uninstall`，使用同一路径；没有用它安装的实例则不加。各实例共用同一个程序文件，所以其他实例会在重启后使用更新。节点可以和连接器并排运行，但不能这样多开。

节点以 **root** 运行，每台机器一个：程序是 `/usr/local/bin/orch-node`，配置是 `/etc/orch/orch.toml`，数据是 `/var/lib/orch-node`。**系统服务**使用 `orch-node.service`。**前台运行**会加上 `--no-service`，并以 root 在终端里用 `/usr/local/bin/orch-node --config /etc/orch/orch.toml run` 启动节点；按 Ctrl+C 停止。对话框里的完整命令包含这个启动。请先停掉已有的服务。要为其他组织服务，请通过**访问权限**共享这台主机，不要安装第二个节点。

### 通过代理连接

连接器和节点通过机器的代理访问系统，以及它们转发到的模型服务。它们读取变量 `HTTPS_PROXY`、`HTTP_PROXY`、`ALL_PROXY` 和 `NO_PROXY`（大写或小写均可）；在 macOS 或 Windows 上没有设置这些变量时，则读取系统的代理设置。它们支持 `http://`、`socks5://` 和 `socks5h://` 这几种代理（用 `socks5h` 时由代理解析域名），代理需要认证时，地址里可以带 `user:password@`。

服务启动时使用的是它的管理器的变量，而不是你 shell 里的变量。Linux 和 macOS 的连接器安装程序、Linux 的节点安装程序和 `orch-connector service install` 会把你 shell 里的智能体变量写进服务。它启动的程序（智能体程序、`git`）会继承这些变量。这些服务文件只有所有者可读，因为智能体的地址里可能包含密码。

- 要使用与 shell 不同的代理，请在安装连接器服务时加上 `--proxy socks5h://proxy.example:1080`；用 `--proxy none` 则所有主机都直连。用 `--no-proxy` 指定要直连的主机。要更改，请重新安装。
- 在 Windows 上，登录任务使用你账号的变量启动。请用 `setx` 设置它们。
- `orch-connector doctor` 会显示网关的每个地址是通过哪个智能体访问的。

## 3. 执行命令，等待机器出现

1. 选择 Orch 可以管理其设置的角色。本机保存的设置始终优先。每个角色的**将其设置交给 Orch**一开始是关闭的，打开它就把这个角色的策略交出去。另一个单独的**专用**开关（**完全控制**）声明这是一台只做这件事的虚拟机或电脑，可以作为隔离边界。这是本机的同意，Orch 之后无法替你打开它。
2. 选择**显示命令**，复制适合那台电脑操作系统的命令，并在那里运行。命令会随你的每个选择而变化，所以请使用完整的命令。它的令牌只能使用一次，与你的选择绑定，并会过期。命令过期后请更换。选择另一个位置也会生成新命令：请使用现在显示的那一条。
3. 第一次连接到达时，Orch 会确认它，关闭对话框并打开这台机器的页面。已保存但仍离线的登记会继续等待。

在 Linux 和 macOS 上，命令里可能带有 `--roles environment,agent --delegate environment,agent --dedicated`。Windows 使用 `-Roles`、`-Delegate` 和 `-Dedicated`。`--delegate-policy`（`-DelegatePolicy`）则把策略的每一个键都交出去。只有在登记被信任之后，连接器才会保存角色及其设置部分。没有选择角色的旧令牌保持之前的默认行为。

以后要更改角色，机器页面会给出 `orch-connector roles set environment,agent,provider`。编辑列表，在那台电脑上运行它，并重启连接器。它重新连接时会报告所选的角色。页面没有远程编辑角色的操作。要添加**节点**，请把主机单独登记一次。

如果对话框提到名为 `public_url` 或 `[[gateway.endpoints]]` 的设置，请让系统管理员把该设置里的示例地址替换掉。在这些地址设置好之前没有可用的命令。人和安装程序使用人们打开的地址。机器使用自己配置的列表，或每次连接时从系统收到的列表。环境跟随它们所在节点的列表，除非节点的配置指定了别的列表。

浏览器和安装程序需要设备信任的证书。机器还会接受 Orch 为它所指定的 Orch 服务提供的证书，无论使用哪个地址。如果用的是公司自己的证书颁发机构，请让管理员在设备上安装它的证书。请保持证书检查开启。

安装程序只允许系统的 HTTP 地址用于 `127.0.0.0/8`、`[::1]` 和 `localhost`。这个地址指向运行命令的那台电脑，所以其他机器需要系统的 HTTPS 地址。节点的这项例外只适用于系统的下载地址，它与网关的连接仍然使用 TLS。

## 修改驱动设置

在节点的**策略**标签页里，机器运营者把这项设置交给 Orch 之后，打开**驱动**即可编辑它的 JSON。对已经报告了配置模式的驱动，无效的字段会在值旁边标出；请修正后再保存。编辑器会保留你的草稿。如果驱动没有报告模式，Orch 无法在这里检查它的连接字段。对连接的更改在节点重启后生效。

## 4. 重新登记同一台机器

对于别人的机器，管理员需要先确认**强制获取访问权限**。这会把他们的名字加入机器的**管理**行，并把这次覆盖记录到审计里。它需要在浏览器会话里选择**以管理员身份**；令牌，或该模式关闭的会话，都不会获得管理员权限。按名字授予的权限会一直保留，直到从**访问权限**里移除。机器角色或设置改变时，它本机保存的策略仍然适用。

如果机器的证书被吊销，或机器离线时间超过续期宽限期而证书已过期，请打开机器页面并选择**重新登记**。仍在宽限期内的证书会在机器下次连接时自动续期。

在那台机器上用它现有的数据目录运行对话框里的命令。它会就地替换身份，并保留设置、策略、登记、名称和页面。正在运行的前台实例会加载新身份；已停止的实例下次启动时使用它。同一台机器回来时，对话框会告诉你。新证书第一次被使用时，旧证书就会失效。

如果它的磁盘丢失了，请在替换的机器上用全新的数据目录运行同一条命令。Orch 会为这台机器保留同一个页面。**添加机器**或**添加主机**生成的命令无法替换已有的身份；请对这台机器使用**重新登记**。

## 5. 停止或完整移除

机器页面的**安装方式**部分列出了它实际的路径和服务命令。

- **连接器。** 默认连接器使用 `orch-connector service stop`、`service start` 或 `service uninstall`。对有名称的实例，请把同一个 `--data-dir` 放在前面。在 Windows 上用 `&` 运行它的可执行文件。
- **节点。** 使用 `systemctl stop orch-node.service` 或 `systemctl start orch-node.service`。

要完整移除**连接器**，请先在 Orch 里吊销它，再用 `orch-connector service uninstall` 卸载它的服务（有名称的实例要带同样的 `--data-dir`）。这会停止并移除服务，但保留数据和身份。删除前先查看它的数据。请保留工作文件夹和其他实例，包括嵌套的 `instances/` 目录。最后一个连接器移除之后，再删除共用的程序。

要移除**节点**，请先在 Orch 里移除它的环境和卷，再移除主机。然后以 root 运行 `systemctl disable --now orch-node.service`，删除 `/etc/systemd/system/orch-node.service`，并运行 `systemctl daemon-reload`。查看这个节点的程序和数据，再把它们删除。如果其他 Orch 程序在使用 `/etc/orch/orch.toml`，请保留它。在前台运行的安装没有要移除的服务。只移除服务会保留登记和已存储的数据，不会移除任何工作。关于自动更新和本地更新命令，见[更新](updates.md)。

若要使用此电脑上已登录的程序，请在添加机器中选择**使用已有登录**，再生成命令。
现有角色控件会显示代理、提供方和环境，并开启代理程序控制；运行命令前可检查这些选择。
连接后选择检测到的程序及归属位置，点击注册。Orch 使用报告的路径进行确认，并一起注册
配置和提供方，保留程序原有登录。若配置已添加而提供方注册失败，重试会复用此配置。
机器的已注册内容中也提供同一流程。提供方页面会显示创建对话前尚需完成的登录或模型选择。
